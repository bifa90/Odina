# الجزء الأول — العقد الملزم

## 1. النطاق: ما يُشحن وما لا يُشحن

**التثبيت ليس التشغيل، والقائمة ليست وعدًا.** الجدول التالي يحدّد **العضوية** فقط؛
وما يثبته المستودع اليوم مذكور في [الملحق ب](#a2).

| # | القدرة | العضوية | الحالة اليوم |
|---|---|---|---|
| 1 | **جدار البيانات** — المحرك، القاعدة المحلية، Bloom، الكاش، المقيم المقيم، IPC، الرصد اللحظي | أساسي، غير قابل للإسقاط | محرك يعمل على ملفات حقيقية؛ لا قاعدة إنتاجية موقّعة ولا خدمة مثبّتة |
| 2 | **جدار السلوك** | أساسي في العضوية، **غير مكتمل** في التنفيذ | لا رصد سلوك عملية بعد |
| 3 | **سطح المكتب** — الرئيسية، مركز التنبيهات، صندوق العزل، الإعدادات واللغات | أساسي | معاينة متصفح وكتالوجات عشر لغات؛ لا تطبيق مربوط بمخزن عزل إنتاجي |
| 4 | **الحماية الاستباقية والاستثناءات** | أساسي | منطق Rust واختبارات؛ لا دليل منع فعلي على Windows |
| 5 | **قائمة Windows Explorer** | أساسي | غير منفّذ |
| 6 | **AMSI Provider** (D66) | أساسي، بشرط بوابة قياس | غير منفّذ |
| — | **تكامل المتصفح** (D48) | إضافة اختيارية | إضافة تعمل مع خدمة تجريبية؛ هدف Firefox `<100ms` لم يتحقق |
| — | **أتمتة الإصلاح والصيانة** | إضافة اختيارية | وصفتان تدريبيتان؛ ليست أتمتة على ملفات المستخدم |
| — | **WDAC Deny-Hash** (D67) | **وضع خبير اختياري فقط** | غير مُثبت؛ يحتاج PoC |

**قواعد النطاق**

1. «أساسي» يعني أن الحزمة العامة لا تُقبل دونه — لا أن كل مكوّن يستهلك موارد دائمًا.
2. «اختياري» يعني أنه لا يُثبَّت ولا يُفعَّل افتراضيًا، وأن الوظائف الأساسية تعمل بلا حساب ولا شبكة ولا إضافة بديلة.
3. الإضافتان **لا تفتحان قبول الأساس ولا تحجبانه**. لكلٍّ تركيبه وإزالته واختباره.
4. WDAC **لا يُقدَّم كإنفاذ قائم** قبل اجتياز PoC على Home وPro.
5. لا يُرقّى بند من «مطلوب» إلى «منفّذ» بلا شاهد جديد.

**حدود ثابتة (D68):** user-mode فقط، بلا درايفر نواة، بلا خدمة مرتفعة دائمة. أي صلاحية
تحتاجها وظيفة تُطلَب بموافقة UAC لمرة واحدة عند الحاجة.

[حدود المكوّنات في Rust](rust-workspace.md) · [جرد الشجرة وأدلّة الفجوات](reviews/policy-audit-v18.md).

## 2. الأهداف ومعايير القبول

**ثلاثة أهداف. لا رابع.** وكل هدف يحمل حالته بصراحة (D56).

| # | الهدف | المعيار | الحالة |
|---|---|---|---|
| 1 | **خفيف على الموارد** | RAM خمول <20MB · CPU خمول ≤0.1% · CPU فحص خلفي <3% · CPU فحص USB ≤5% ذروة | مطلوب |
| 2 | **قوي في الكشف، خاصة USB** | ≥99.5% على Golden Set · 100% من عائلات USB المعروفة | مطلوب |
| 3 | **تغطية واسعة** | ≥250 عائلة مُغطّاة بإجراء · ≥8 عينات مستقلة لكل عائلة | مطلوب |

**«الحجم وسيلة، والقوة غاية» — لكن القيد الحقيقي هو الخفة لا الميغابايتات.**
لهذا لا يوجد هدف رقمي لحجم قاعدة التهديدات (D61)، والهدف الرقمي الوحيد هو
**≤25MB للمُثبِّت كهدف لا كسقف** (D60). التفصيل في §6.

**القاعدة الذهبية:** لا تُقلَّص قاعدة البيانات من أجل الحجم، ولا تُضخَّم من أجل الكمال.

### 2.1 حالة القياس

**لا رقم في هذا القسم ادعاء.** الأرقام أهداف قبول؛ ما قيس فعلًا مذكور في
[`docs/perf/`](perf/) وبتاريخ وعتاد. المتاح اليوم: متجه G1 و20 ملفًا سليمًا — لا يكفي
لادعاء حساسية أو إنذار كاذب إنتاجي.

## 3. أسس الثقة — دستور الواجهة (D28، D78، D80، D81)

هذا القسم **دستور** لا توصية. إن تعارضت قاعدة تصميم معه — تُحذف القاعدة، لا يُخفَّف الأساس.

### 3.1 الوضوح — ليست العبارة واضحة، بل النتيجة

| المبدأ | القاعدة |
|---|---|
| النتيجة أولًا | «عُزل File.exe» نعم · «تم اكتشاف كائن خبيث عبر محرك التوقيعات» لا |
| لا مصطلح بلا معنى | يُشرح عند الطلب فقط، لا في السطر نفسه |
| لا إخفاء | لا قرار يُتخذ باسم المستخدم بلا أن يراه |
| الصدق في الالتباس | «لا نعرف» جملة مقبولة ومطلوبة |
| جملة واحدة | كل تنبيه = جملة واحدة + اسم الملف |

### 3.2 البساطة — الأقل عددًا، لا الأقل محتوى

| المبدأ | القاعدة |
|---|---|
| **حد أقصى زرّان** | زرّان + «لماذا؟». ويجوز **دمج خيارات تحت زر أساسي بسهم صغير** عند الحاجة (D78) |
| خيار واحد واضح | زر أساسي واحد في كل شاشة |
| **صفر إعداد مطلوب** | كل شيء يعمل بالافتراضي؛ الضبط في «متقدم» (D80) |
| قوائم قصيرة | لا قائمة تتجاوز 7 عناصر بلا تجميع |
| الخيار لا السؤال | نعرض خيارين ونتيجة كل منهما |
| الحفظ لا يُطلب | كل تغيير يُحفظ تلقائيًا |

### 3.3 الطمأنينة لا الإزعاج (D81)

- **عدم تكرار التنبيهات أثناء الفحص اليدوي**: امتداداً لهذا المبدأ، عند فحص عنصر أو مجلد أو قرص يدوياً، تظهر النتائج داخل لوحة الفحص نفسها دون إشعار جانبي مكرر (Toast)، إلا إذا كشف الفحص السلوكي امتداد التهديد إلى مواقع أخرى (مثل بدء التشغيل).

| المبدأ | القاعدة |
|---|---|
| الصمت هو الافتراضي | بلا حدث = بلا نافذة |
| لا تنبيه بلا فعل مطلوب | تنبيه بلا قرار = إزعاج |
| **سقف الإشعارات** | ≤3/يوم؛ **المؤكد والحرج لا يُحتسبان فيه** |
| لا نافذة Modal أبدًا | Toast أو Inline فقط |
| لا تكرار | تنبيه واحد لكل حدث |
| بلا تسويق | لا «قيّمنا»، لا اشتراك |
| يعتذر عند الخطأ | إن أوقفنا برنامجًا سليمًا، نعتذر ونُصلح في نفس الشاشة |

### 3.4 معرفة العواقب قبل الضغط

| المبدأ | القاعدة |
|---|---|
| عاقبة كل زر مكتوبة | «المنع — لن يعمل هذا البرنامج بعد الآن» |
| العاقبة قبل الزر لا بعده | لا نُخبره بما فات |
| غير القابل للتراجع يُعلَّم | «حذف نهائي» وحدها بلا رجعة |
| الأمان هو الافتراضي المميّز | الخيار الآمن هو الزر الأساسي المرئي |
| لا لوم على المستخدم | نقول ما حدث لا من السبب |
| بيانات كافية للقرار | اسم + مسار + سبب واحد واضح |

### 3.5 سلّم الأولوية عند التعارض

```
1. أمن المستخدم الفعلي (لا يضرّه Odina أبدًا)
2. عدم الإزعاج      ← يسبق الوضوح
3. الوضوح
4. معرفة العواقب
5. البساطة
6. الجمال
```

**لماذا عدم الإزعاج يسبق الوضوح؟** لأن الوضوح يُطلَب عند الحاجة، والإزعاج يستهلك
الثقة فورًا ولا يُستردّ. مكافح يُزعج = مكافح يُعطَّل = صفر حماية.

### 3.6 بوابة قبول إلزامية (Trust Gate)

كل شاشة أو PR يخالف أيًّا من التالي **يُرفض**:

- [ ] كل تنبيه = جملة واحدة + ≤ زرّين (+ سهم خيارات عند الحاجة)
- [ ] لا شرح داخل الواجهة — التلميح موجود والشرح عند الطلب
- [ ] كل زر يحمل عاقبته المكتوبة
- [ ] لا Modal · لا إشعار بلا قرار · لا تكرار
- [ ] الخيار الآمن هو الافتراضي المرئي
- [ ] لا مصطلح تقني بلا تعليل
- [ ] عند الشك: احذف النص، لا تُضف شرحًا

## 4. القواعد غير القابلة للكسر

أي كود يخالف هذا القسم **يُرفض في المراجعة**، بلا استثناء ولا تصويت.

### 4.1 الجدران الثلاثة ودورة جدار السلوك (D3، D49، D50)

**الجدار 1 (البيانات) والجدار 3 (الاستباقية) فعّالان افتراضيًا ما دامت الحماية عاملة.**
الأول يستجيب للأحداث ولا يستهلك CPU بجولات استطلاع دورية.

**عند تقييم ملف:** يأتي جدار قاعدة البيانات أولًا؛ تُحال الأدلة إلى التحليل السلوكي
عند انطباق قواعد التقييم، وتُطبَّق الاستباقية عند نشاط يطابق قاعدة. المقيم يستمع
للأحداث بدل الاستقصاء المستمر. **لا نُشغّل ملفًا مشبوهًا للحصول على ملاحظة.**

**ترتيب فحص الملف لا يحدّد عمر جلسة الرصد:** تأكيد الجدار الأول لا يحتاج إعادة إثبات
بالسلوك، لكنه قد يفتح حادثة تستلزم رصد الجهاز.

**الجدار 2 (السلوك) جزء من التثبيت، لا من الإضافات.** الوضع الافتراضي «عند الحاجة».
قبل تمكين الوضع الدائم نعرض العاقبتين معًا: «المراقبة المستمرة قد تزيد استهلاك موارد
جهازك. حتى دونها، ينشط جدار السلوك تلقائيًا عند الخطر». لا اختيار مسبق للدائم،
ويمكن التراجع دون إزالة الجدار.

**أسباب التنشيط المؤقت الأربعة:**

| السبب | النطاق | متى يزول؟ |
|---|---|---|
| المستخدم يفحص ملفًا مباشرة (ومن ذلك أمر Explorer) | مهمة ذلك الملف، لا جرد القرص | عند انتهاء الفحص أو إلغائه بأمان؛ وإن ثبتت إصابة يتسلّمها سبب مستقل |
| إصابة الجهاز | حادثة مؤكدة وما يتصل بمصدر الضرر | بعد تحييد الخطر وحسم النتائج والتحقق من زوال الإصابة |
| إدخال عنصر خطر (فلاشة أو قرص قابل للإزالة) | العنصر المعني وما يتصل به | عند انتهاء التحقق أو فصل الوسيط؛ لا يُسقط حادثة مفتوحة |
| الفحص السريع للملفات المفتوحة والنقاط الخطرة | الملفات المفتوحة وبدء التشغيل والمهام والمفاتيح الحساسة | عند انتهاء الفحص أو إلغائه بأمان |

**قواعد دورة الحياة**

1. **تفضيل الدائم يُحفظ منفصلًا عن أسباب التنشيط المؤقت.**
2. الجدار نشط ما دام سبب واحد قائمًا، ويعود خاملًا بعد آخر سبب.
3. تكرار الحدث أو تعذّر فحصه **لا يحوّل الرصد المؤقت إلى دائم**.
4. عند الفشل: اعرض التغطية الفعلية ولا تصدر حكم نجاح. انتهاء مهمة لا يغلق حادثة.
5. **إسكات التنبيهات لا يُغيّر حالة الجدار.**
6. **إيقاف الحماية الصريح النافذ أسبق من أي مشغّل أو ردّ متأخر** (§8).
7. استثناء لقاعدة واحدة لا يطفئ الجدار الأول ولا يغيّر تفضيل الجدار الثاني.

**حدّ الإذن:** طلب D48 الأول يقرأ حكمًا منشورًا فقط، فليس فحص ملف مباشرًا ولا يبدأ رصدًا.
إثبات الجدار يتطلب أحداث تشغيل حميدة مرصودة، لا واجهة تحمل اسمه.

### 4.2 الحماية الاستباقية — قواعد Prevent-First (D45، D46)

| القاعدة | التنفيذ | القابلية للتجاوز |
|---|---|---|
| **A1 — محركات السكريبت** | WSH = Restricted · PowerShell من مصدر خطر = Constrained Language · ماكرو Office غير الموقّع = حظر | استثناء جراحي لكل محرك على حدة؛ A1-WSH لا يفتح A1-PowerShell |
| **A2 — إدخال وسيط** | وصول الجهاز يوقظ جدار البيانات ومسار USB؛ العنصر الخطر ينشّط جدار السلوك مؤقتًا | يخضع لإيقاف الحماية الصريح؛ لا ثقة بالاسم وحده |
| **A3 — مجلد التنزيلات** | كل ملف **أُضيف** إلى `Downloads` مشتبه حتى يُثبت العكس | سماح بمصدر محدد ووقت محدد |
| **A4 — الفحص الدوري الصامت** | كل ساعتين: فحص سريع للملفات المفتوحة ونقاط الخطر | تغيير التكرار أو استثناء الجدولة؛ لا يُلغى فحص مباشر |
| **A5 — بدء الفحص الدوري** | بعد ~5 دقائق من الإقلاع | لا |
| **A6 — الحذر لا الشجاعة** | عند الشك: المنع أولًا ثم السؤال | إرخاء فقط؛ سماح بالشك مرفوض |

**الأنشطة التسعة (D46):** 3 تُمنع تلقائيًا · 4 مسموحة ويُوصى بمنعها · 2 مسموحان والمنع اختياري.
فحص إصابة مؤكدة يمنع التسعة حتى نجاح الفحص والتنظيف والإصلاح. التفصيل في
[مواصفة الحماية §2.3.1](spec/protection-policy-v1.md).

**قيود A3 الإلزامية حتى لا يتحول إلى إزعاج:**

- «مشتبه» **لا يعني «مُحجَّر»**: لا تنفيذ تلقائي + إشعار هادئ + مسار «أنا أعرفه» بضغطة.
- لا تنبيه متكرر لنفس الملف — مرة واحدة لكل ملف/إصدار ثم بصمت.
- ملفات المتصفح المؤقتة (`.crdownload`, `.part`, `.tmp`) **مستثناة** من A3.
- A3 لا يعمل على مجلدات أضافها المستخدم إلى قائمة الثقة.

**ميزانية الاستباقية:** ≤1% CPU متوسطًا · ≤8MB RAM · **صفر I/O في الخمول**؛ والفحص
الدوري يعمل بأولوية خلفية ويتوقف عند حمل النظام >70% أو بطارية <20%.

### 4.3 لا تقليص للقاعدة من أجل الحجم

- أي قرار لتقليص الحجم يجب أن يجتاز: *«هل يقلّل من كشف عائلة USB نشطة؟»* — إن كانت الإجابة نعم، فهو **مرفوض**.
- كل إصدار يصاحبه **Value Manifest** يعرض ما كُسب وما لم يُحذف.
- **العكس صحيح أيضًا:** لا تضخيم للحجم من أجل الكمال (D59).

### 4.4 قاعدة البيانات المحلية مقدّسة

- ML والسحابة **طبقات مساعدة**، لا بدائل عن القاعدة المحلية.
- Smadav أخطأ حين استبدل القاعدة بـAI؛ لا نكرر الخطأ.

### 4.5 لا محتوى ملفات في التقارير

- التقارير تحوي **بصمات ومؤشرات فقط**: لا بايتات، لا مسارات كاملة، لا هوية.
- كل تقرير **JSON موقّع**.
- **لغة الواجهة ليست بيانات هوية** ولا تُرسل إلا كرمز مجهول (`ui_lang`) وبموافقة Opt-in.

### 4.6 WSH Restricted افتراضيًا

Restricted عند التثبيت (لا Disabled، لا Enabled). Disabled خيار صريح بعد تحذير.
Full Block في وضع الخبير.

### 4.7 التصنيف ثلاثي، ومِحوران لا محور

**المحور الأول — درجة اليقين:**

| الدرجة | الدليل |
|---|---|
| مؤكد ببصمة | تطابق SHA-256 كامل؛ يتقدم على كل المؤشرات |
| مؤكد تشغيليًا | عتبة الدرجة؛ ليس ادعاء تطابق بتّي |
| مشتبه بشدة | أوزان وسقوف ومنطقة تدرّج |
| مشتبه | أوزان وسقوف ومنطقة تدرّج |

**المحور الثاني — درجة الخطورة:** محور مستقل تمامًا.

| الخطورة | مثال | الإجراء الافتراضي |
|---|---|---|
| حرج | ransomware · worm · USB spreader | منع فوري + معالجة + إشعار لا يختفي |
| عالٍ | trojan · backdoor · keylogger | منع فوري ثم معالجة |
| متوسط (PUA-Risk) | كراك · أداة تهكير · keygen | تنبيه + **لا اعتبار تلقائي للإصابة** (D79) |
| منخفض | adware · أداة مقلقة | إشعار هادئ + خيار إزالة |

**لماذا الفصل؟** لأن «مؤكد» ليس مرادفًا لـ«احجره». كراك مؤكد البصمة = خطورة متوسطة =
لا يُحجَر تلقائيًا. خلط المحورين كان سيجعل Odina يحجر برامج المستخدم الشرعية.

### 4.8 اللغة ليست مؤشر ثقة (D83، D84، D85)

**ملزم:**

1. لغة النص، ولغة المسار، ولغة الواجهة، و`locale` الجهاز، والمنطقة الزمنية: **لا ترفع درجة ولا تخفضها**.
2. لا عمود «لغة» في قاعدة الثقة ولا في قائمة الثقة ولا في معايير التصنيف.
3. ممنوع استخدام اللغة كخاصية في ML.
4. انتحال اللغة هجوم معروف؛ الحماية منه هي §4.7: الحكم بالبصمة والسلوك، لا بالشكل.
5. اللغة تُستخدم في ثلاثة مواضع فقط: اختيار لغة الواجهة · ترتيب أولوية نسخ التعريب · ترتيب أولوية تحميل قواعد YARA **كأولوية أداء لا تصنيف**.

### 4.9 قواعد التعريب

1. **الترجمة البشرية المراجَعة فقط** في النصوص الأمنية (D83).
2. كل نص أمني في كل لغة يحمل نفس المعنى ونفس مستوى التحذير. ترجمة تُخفّف خطرًا = **خطأ أمني** لا لغوي.
3. لا دمج نصوص مترجمة على الهواء؛ كل جملة كاملة = مفتاح واحد كامل.
4. فحص pseudo-localization إلزامي في CI.
5. لا يُشحن إصدار بلغة واجهة كُسر تخطيطها.

### 4.10 ترخيص البيانات الخارجية (D70)

**قواعد ClamAV تُشحن بيانات منفصلة بترخيصها ولا تُربط شيفرةً.** GPLv2 غير متوافق مع
AGPLv3 في الربط. أي محاولة لدمجها في الشيفرة **مرفوضة** بموجب هذا البند، لا بموجب
ملاحظة مخاطر.

<a id="s5"></a>
## 5. المعمارية

أربع طبقات، وليست قائمة ميزات:

```
الطبقة 0: البيانات الوصفية — Bloom → Hash Index → Fuzzy Index
          تحسم 99% من الملفات في < 1μs
              ↓ (تطابق جزئي فقط)
الطبقة 1: فحص الكود — PE Parsing → Entropy → Strings → YARA → Signature
              ↓
الطبقة 2: فحص السلوك — Emulation / API Hooks / Lightweight Sandbox
              ↓
الطبقة 3: قرار المستخدم — إيقاف مؤقت → تنبيه واضح → سماح/منع/لماذا
```

**اللغة تعمل في الطبقة 3 فقط** (فهم القرار) وفي ترتيب أولوية قواعد الطبقة 1 — لا في إسناد الثقة.

### 5.1 نموذج التسجيل — 10 مؤشرات

| # | المؤشر | الوزن |
|---|---|---|
| 1 | الحجم الدقيق بالبايت | 10% |
| 2 | نمط اسم الملف | 8% |
| 3 | نمط المسار | 8% |
| 4 | سمات الملف | 7% |
| 5 | بصمة الرأس (SHA-256 أول 4KB) | 15% |
| 6 | بصمة الذيل (SHA-256 آخر 4KB) | 8% |
| 7 | بصمة PE / Imphash | 12% |
| 8 | التشابه الضبابي (TLSH) | 22% |
| 9 | غياب التوقيع الرقمي | 5% |
| 10 | بصمة السلوك المعلن (Imports/Strings) | 5% |

**قيد ملزم (D84):** المؤشرات 2 و3 و10 تُحلَّل **خصائص بنيوية** — طول، بنية، تكرار —
بتطبيع كامل. تعريب المسار أو اسم الملف **لا يزيد الوزن ولا ينقصه بذرّة**.

### 5.2 العتبات — جدول واحد لا جدولان (D76، D77)

| النطاق | الإجراء | الإطلاق | التسجيل |
|---|---|---|---|
| ≥99% | منع فوري + معالجة D47 | لا | — |
| **80–98.9%** | **منع فوري + تحليل سلوكي في الخلفية (D76)** | **لا إطلاق بلا قرار مستخدم** | Ring Buffer |
| **50–79.9%** | **لا منع — تنبيه: تجاهل / فحص عميق (D77)** | نعم، الملف يعمل | Ring Buffer + مراقبة تكرار |
| <50% | مرور صامت | نعم | Ring Buffer |
| لا تطابق | مرور آمن | نعم | تسجيل |

**أقل من 50% لا يُعرض على المستخدم إطلاقًا.** عرض ما دون العتبة = إزعاج = فقدان ثقة.

### 5.3 الترشيح المتتالي — سرّ الخفة

```
فحص أهلية التلميح → مسبار البادئة عند اللزوم → تحقق دقيق من المحتوى → قرار
```

الإيجابية **مرشّح** لمطابقة دقيقة وليست حكمًا؛ السلبية لا تُسقط فحوص المؤشرات الأخرى.
تلميح الكاش لا يمنح الثقة للملف. الحكم المنشور له نطاق وفترة صلاحية؛ التغيير أو
الفجوة يبطله. انظر [حدود الفهرس](perf/b9-prefix-cache.md).

### 5.4 حدود الإنفاذ — الصياغة الملزمة (D69)

> **منع عند حدود إنفاذ معلومة: AMSI للسكربتات، WDAC للتنفيذ بعد نشر السياسة.
> لا منع على مستوى النواة.**

| القدرة | مع درايفر نواة | **مسارنا (user-mode)** |
|---|---|---|
| فحص عند الكتابة | فوري لكل عملية | شبه فوري (USN/ETW) |
| منع تنفيذ exe معروف | مضمون | عبر WDAC **بعد نشر السياسة** (وضع خبير) |
| منع سكربت قبل تنفيذه | نعم | **عبر AMSI** (أساسي، ببوابة قياس) |
| منع عملية مجهولة قبل أول بايت | نعم | لا — تُكتشف عند الكتابة/التشغيل |
| حماية العبث | قوية (نواة) | متوسطة (خدمة مقيّدة + ACL + Watchdog) |

**حدود لا تُخفى:** WDAC يحتاج صلاحية مدير ونشر سياسة (قد تحتاج إعادة تشغيل)؛ AMSI
يغطي السكربتات لا كل الملفات التنفيذية؛ المنع يحدث عند حدود معروفة وقد يفوّت تقنيات
تهرّب — نُعلن ذلك ولا ندّعي كمالًا.

<a id="s6"></a>
## 6. قاعدة البيانات والحجم

### 6.1 ميزانية الحجم — ثلاث طبقات (D59، D60، D61، D62، D63، D64)

> **قرار المالك:** «الحجم وسيلة والأمان غاية». **هدف** المُثبِّت ≤25MB، **ولا يُمنع
> أكبر عند الضرورة**؛ وتجاوز الهدف يحتاج سطر مبرر في Value Manifest.

| الطبقة | المعنى |
|---|---|
| **① هدف** | ≤25MB للمُثبِّت. طموح هندسي لا حدّ فشل |
| **② سقف مرن** | تجاوز الهدف جائز بمبرر موثّق في Value Manifest + قرار مالك |
| **③ لا سقف خارجي** | لا رقم يفشل البناء. الحجم لا يقيّد الكشف أبدًا |

**ما يبقى غير قابل للتفاوض بعد رفع السقف:**

1. **§2 هدف الخفة كما هو:** RAM خمول <20MB، CPU خمول ≤0.1%، CPU فحص <3%. الحجم المفتوح ليس ترخيصًا للثقل.
2. **§4.3:** لا تقليص للقاعدة من أجل الحجم، ولا تضخيم من أجل الكمال.
3. **الاحترام:** لا نُجبر مستخدمًا على تنزيل مئات الميغابايت على حاسوب قديم.

**لا هدف رقمي لحجم قاعدة التهديدات (D61).** الهدف المعلن هو خفة **موارد التشغيل**
— RAM وCPU وI/O — لا موارد التخزين.

### 6.2 بوابة «الأصغر الممكن» — G1/G2/G3

لا سقف رقمي، لكن **لا نموّ بلا مبرر موثّق**:

| البوابة | السؤال | إن فشل |
|---|---|---|
| **G1 — الكشف** | هل الزيادة تُضيف كشفًا لعائلة أو تهديد لم يكن مُغطّى؟ | لا ← **ارفض الزيادة** |
| **G2 — الكفاءة** | بايت لكل تهديد مُغطّى: هل بقي ثابتًا أو تحسّن؟ | تدهور >5% ← إعادة ضغط أو تصميم — **إلا** بمبرر موثّق لعائلة جديدة أو كشف حرج (D63) |
| **G3 — الخفة الحيوية** | هل ترفع RAM الخمول أو زمن P0؟ | نعم ← **ارفض** بموجب §2 |

**قاعدة الرفض (D62):** لا زيادة بلا **سطر مبرر في Value Manifest**. لا يوجد رفض آلي
عند نسبة محددة؛ المراجع يحكم على المبرر. الرقم وحده لا يرفض ولا يُقبل.

**وسائل الحفاظ على الصغر — إلزامية لا اختيارية:**

- ضغط **zstd** لكل قاعدة، و**mmap للقراءة فقط** — لا تحميل في RAM.
- **Bloom أولًا** ثم الفهرس: لا تُقرأ بايتات القاعدة إلا عند تطابق.
- بناء الـSetup بـ LZMA/BCJ2 بقيم مضغوطة مُعدّة يدويًا.
- `strip` · `-Os` · `panic=abort` · بلا `std` حيث أمكن.
- لا خطوط زائدة عن [الملحق ج](#a3)، لا صور نقطية كبيرة، لا أيقونات مكرّرة.
- نظام إضافات للمحتوى الكبير بدل تضخيم المُثبِّر.
- قياس حجم كل مكوّن ورقمه في Value Manifest لكل إصدار — لا انحدار صامت.

### 6.3 المستويات الثلاثة (مناطق داخل قاعدة واحدة)

| المستوى | المحتوى | الحجم/سجل | العدد المستهدف |
|---|---|---|---|
| **A: كامل** | 10 مؤشرات + وصف سلوكي + معرّف عائلة | 550B | 100K |
| **B: مبسّط** | Hash + حجم + عائلة | 80B | 800K |
| **C: hash فقط** | SHA-256 | 36B | 2M |

الأرقام أعلاه **تصميم لا قياس**. المقارنة بين الحجم الخام والمضغوط مسألة قياس لا حساب؛
لا يُستنتج حجم الحزمة من مجموع سجلات المستويات.

### 6.4 تنسيق الوصول (D103)

- `signatures.db`: **صيغة مخصصة للقراءة فقط** — رأس بإصدار، مصفوفة بصمات مرتّبة، منطقة سجلات،
  **بلا ضغط داخلي**؛ النقل ZIP. تُقرأ بـmmap عند توفّره، و**قراءة متتابعة احتياطية** على
  الوسائط وأنظمة ملفات الشبكة، لأن الخريطة قد تُفشل هناك.
- `hashes.bloom`: مرشّح سلبي من **نفس جيل** الفهرس؛ سالبُه لا يُسقط بقية المؤشرات.
- `device_trust.db`: مخزن صغير قابل للكتابة بكتابة ذرّية؛ لا يُشترط SQLite.
- **لا جدول ولا عمود «لغة» في أي منها** (§4.8).

### 6.5 خيارات بيانات الكشف

الاسم `public` في ZIP يميّز ثنائية خالية من القياس، **ولا يعني أنها الحزمة الأساسية المكتملة**.

- قاعدة مختصرة (Tier C فقط) — لمن يريد أصغر بصمة تخزين.
- كاملة (افتراضية، Tier A+B+C).
- خبير (عائلات تاريخية + YARA كاملة) — Opt-in منفصل.

## 7. USB — جوهر التخصص

### 7.1 الاستيقاظ

- **الزناد:** `WM_DEVICECHANGE` / `udev` / `DBT_DEVICEARRIVAL`.
- **الاستجابة:** <50ms.
- **التفعيل:** عند وصول وسيط والحماية عاملة. نشرع في تقييم الجهاز؛ ولا يوقظ الوصول وحده جدار السلوك إلا عند توافر سبب §4.1.

### 7.2 حالة الثقة بالجهاز

| الحالة | السلوك |
|---|---|
| Untrusted (جديد) | فحص كامل + منع تنفيذ حتى انتهاء P1 |
| Scanning | منع تنفيذ مؤقت |
| Trusted | فحص delta للتغييرات فقط |
| Suspicious | تشديد مؤقت في نطاق خطر الوسيط؛ لا يتغير التفضيل الدائم |
| Quarantined | منع كامل + خيار «أنا أثق به» |

**بصمة الجهاز:** VendorID + ProductID + VolumeSerial + Capacity. **لا لغة، لا منطقة.**

### 7.3 الفحص المتدرّج

| الأولوية | المحتوى | المدة |
|---|---|---|
| **P0** | `.lnk` `.exe` `.scr` `.bat` `.vbs` `.js` `.cmd` `autorun.inf` في الجذر | <3 ثوانٍ |
| **P1** | كل التنفيذيات في كل المجلدات | <15 ثانية |
| **P2** | مستندات + أرشيفات | <2 دقيقة |
| **P3** | بقية الملفات | متى توفّرت الموارد |

**الميزانية (D54):** ≤30MB إضافية فوق خط الأساس · ≤50MB ذروة إجمالية · ≤5% CPU ·
خفض تلقائي عند حمل النظام >70%.

**خط الأساس** = ذاكرة العملية قبل إدخال الوسيط، على جهاز مرجعي معلن في تقرير القياس.

**أسماء الملفات غير اللاتينية** تُعامَل كمًا ونوعًا واحدًا: لا تُصنَّف أعلى لكونها غير
إنجليزية، ولا تُتجاهل لكونها غير مقروءة في السجل. النص يُسجَّل **UTF-8 escaped**.

### 7.4 القواعد السلوكية الثمانية

| القاعدة | الوزن |
|---|---|
| B_EXEC_FROM_REMOVABLE | 25% |
| B_LNK_SUSPICIOUS | 20% |
| B_HIDDEN_EXE_ROOT | 20% |
| B_DOUBLE_EXT | 15% |
| B_FAKE_FOLDER | 20% |
| B_SELF_COPY_TO_USB | 20% |
| B_USB_WRITE_BURST | 15% |
| B_AUTORUN_CREATE | 25% |

**سؤال مفتوح Q19:** تعارض `autorun.inf` سليم غير موقّع بين «دليل الإصابة» و«سياسة منع
التشغيل». يُحسم عند بوابة K4، ولا يُبنى عليه حكم تلقائي قبل الحسم.

## 8. حماية العبث والإيقاف

### 8.1 حماية العبث — إلزامية ولا تُوقف أبدًا

| الآلية | التنفيذ |
|---|---|
| توقيع العمليات | أوامر الإيقاف من عمليات موقّعة فقط |
| حماية الخدمة | `SERVICE_CONFIG_FAILURE_ACTIONS` + ACL |
| حدود الصلاحية | user-mode فقط (D68) |
| حماية Registry | ACL + مراقبة تغيير |
| Watchdog | إعادة تشغيل تلقائي |
| كشف الحقن | منع حقن في عمليات Odina |
| كلمة مرور الإعدادات | اختيارية في وضع الخبير |
| حماية حزم اللغة | حزم `locales/*.pak` موقّعة؛ **لا يمكن تحميل حزمة غير موقّعة** |

**ناقل هجوم صريح:** حزمة لغة مزيفة تُعيد تسمية زر «منع» إلى «سماح». لهذا التوقيع شرط تحميل لا تحسين.

> «إن استطاع فيروس إيقاف الجدران، فالجدران لم تكن موجودة.»

### 8.2 الإيقاف — مستويان (D71، D72، D73، D74)

> **مبدأ المالك:** وضوح ومرونة، لا تقييد وإزعاج — والمسؤولية على المستخدم مع تنبيهه.

| المستوى | ما يتوقف | ما يستمر | المدد |
|---|---|---|---|
| **1 · إسكات التنبيهات** | التنبيهات فقط | **قواعد الجدران الثلاثة كما هي** | 10د · 30د · ساعة · حتى إعادة التشغيل |
| **2 · إيقاف الحماية** | الفحص والمنع والتنبيه | **الخدمة تعمل في وضع مقيّد: حماية العبث فقط** | 30د · ساعة · حتى نهاية ساعة الذروة · حتى إعادة التشغيل |

**«الخدمة خاملة» وصف ممنوع (D71).** حماية العبث تحتاج خدمة نشطة — Watchdog وإجراءات
الفشل ومراقبة Registry لا تعمل من عملية ميتة.

**قواعد ملزمة على المستوى الثاني:**

1. **شاشة تحذير حمراء إلزامية** — ثلاث جمل: ماذا يتوقف · المسؤولية عليك · الإرجاع بضغطة.
2. **لا مدة دائمة.** أقصى شيء = إعادة التشغيل.
3. **الإرجاع بلا كلمة مرور وبضغطة واحدة.**
4. **لا صندوق «أوافق»، لا نافذة تهويل ثانية، لا عدّاد يمنعه.** نُخبره ونمضي.
5. **حماية العبث لا تُوقف في أي مستوى.**
6. **عند العودة (D74):** فحص سريع هادئ + مقارنة طوابع وأحجام في مجلدات الخطر + ملف
   USN إن كان النطاق سليمًا، وإلا فحص موجَّه. **لا مسح كامل أعمى.**
7. **كل إيقاف يُسجَّل محليًا** (متى، أي مدة، ومتى عاد) — السجل للمستخدم لا تقرير عنه.
8. **ملف مصاب أثناء المستوى الأول (D73):** يُحتوى **فورًا وبصمت**؛ **الحرج وحده**
   يُظهر تنبيهًا واحدًا؛ والبقية في ملخص واحد عند العودة. لا يُترك بلا معالجة.

**حالات يُرفض فيها الإيقاف:**

| الحالة | الرسالة |
|---|---|
| ملف معزول لم يُحسم | «يوجد ملف معزول لم تحسمه بعد. راجعه أولًا.» |
| فحص جارٍ | «هناك فحص جارٍ. انتظره أو أوقفه أولًا.» |
| تهديد لم يُعالَج | «يوجد تهديد لم يُعالَج بعد.» |

**مسار الخروج (D72):** في كل حالة من الثلاث، يبقى للمستخدم خيار صريح
**«أوقفه على مسؤوليتي»** بعد **تأكيد مزدوج**. نحن نطلب منه إنهاء ما بدأه، ولا نسجنه
شهرًا بسبب ملف واحد. الإيقاف في هذه الحالات لا يتركه بلا حماية فقط، بل يمنعه من رؤية
ما سيُكتشف — ولهذا نطلب تأكيدًا لا إذنًا.

**التذكير:** إشعار واحد قبل 5 دقائق من العودة. **ولا تذكير بعد القرار** — من يُعاتَب
على قراره يُطفئ الخدمة من مدير المهام فيخسر كل شيء.

### 8.3 مراجعة النفس (Self-Integrity)

- كل ملفات Odina لها بصمات وأحجام متوقعة موقّعة داخل حزمة الإصدار.
- تُفحص في كل دورة للجدار الأول بتكلفة <5ms (بصمات محسوبة مسبقًا).
- عند اكتشاف تخريب: تنبيه عالٍ + إيقاف الثقة بالذات (وضع محافظ) + مسار «إصلاح فوري» بإعادة تنزيل موقّعة.
- **لا يُصلح نفسه صامتًا** — يطلب من المستخدم ويسجّل الحدث.

<a id="s9"></a>
## 9. تفاعل المستخدم والتنبيه

> كل ما في هذا القسم مقود بـ§3. عند أي تعارض، §3 يحكم.

### 9.1 شاشة الحماية

تُظهر: حالة جدار البيانات وتغطية المقيم · حالة جدار السلوك (**غير متاح / خامل / نشط
لهذه المهمة / دائم باختيارك**) · حالة الاستباقية والاستثناءات السارية.

**لا تعرض «محمي» إذا انقطع IPC أو لم تكتمل التغطية.** في الإعدادات زر لتغيير المراقبة
المستمرة بعد التحذير المزدوج (§4.1)، وليس زرًا لحذف الجدار.

### 9.2 التنبيه — جملة واحدة، وبلا حذف إطلاقًا

*(امتداد عملي لتصنيف المحورين في `§4.7`)*:
- **ملف مصاب بفيروس بشكل مؤكد (وليس ملف الفيروس نفسه)**: يظهر في لوحة إشعار التنبيهات زر **(عزل)** وزر **(معالجة)**.
- **ملف هو فيروس أساساً (برمجية خبيثة مستقلة)**: يظهر في لوحة إشعار التنبيهات زر **(فحص السجل)** وزر **(صندوق العزل)**.
- **منع تكرار التنبيهات أثناء الفحص اليدوي**: عند فحص عنصر أو مجلد أو قرص يدوياً، تظهر التهديدات المكتشفة داخل لوحة الفحص نفسها فقط ولا يُصدر إشعار جانبي مكرر، **إلا** إذا كشف الفحص السلوكي اللاحق امتداد التهديد إلى مواقع أخرى (مثل ملفات بدء التشغيل).

```
برنامج يحاول الوصول إلى ملفاتك
"PhotoTool.exe" يعدّل ملفات في المستندات — أوقفناه مؤقتًا.
[ السماح ]  [ المنع ]   معزول   لماذا؟
```

**قواعد ملزمة:**

- لا مصطلحات تقنية في الواجهة الرئيسية.
- **لا زر «حذف» في أي تنبيه — بأي حال — ولو كان التهديد مؤكدًا** (D26).
- **زرّان كحد أقصى** + «لماذا؟» (+ سهم خيارات عند الحاجة، D78).
- مدة الظهور قابلة للضبط، والقرار الآمن عند الانتهاء **حسب الخطورة لا رقم واحد**.
- موقع التنبيه يتبع لغة الواجهة واتجاه سطح المكتب.
- لا تنبيهان لنفس الحدث — التجميع إلزامي.
- وضع «عدم الإزعاج» يخفي المعلوماتي فقط، ولا يخفي المؤكد أو المشتبه بشدة.
- لا نافذة Modal أثناء ملء الشاشة (Toast أولًا).

**جدول القرار عند انتهاء المهلة:**

| نوع التنبيه | المدة | القرار عند الانتهاء | الأزرار |
|---|---|---|---|
| مؤكد (≥99%) | لا يختفي | منع التشغيل ومتابعة المعالجة | **زر واحد: «متابعة المعالجة»** |
| مشتبه بشدة (80–98.9%) | 60 ثانية | منع | السماح · المنع |
| مشتبه (50–79.9%) | 30 ثانية | **لا منع** — يُسجَّل | تجاهل · فحص عميق |
| خطر متوسط (كراك) | 30 ثانية | لا اعتبار تلقائي للإصابة | **اسمح به · اعزل** (D79) |
| معلوماتي | 10 ثوانٍ | تجاهل بصمت | — |

**صف الكراك بالتفصيل (D79):** الزرّان هما «اسمح به» و«اعزل»، والتوصية البصرية للعزل.
وبجانب «اسمح به» **سهم صغير** يحمل خيارًا إضافيًا واحدًا: **«موثوق — اسمح دائمًا»**.
وصف «انقله جانبًا» **ممنوع**: الاحتواء قرار يُسمّى باسمه، لا بصيغة ملطّفة.

### 9.3 صندوق العزل — الحذف هنا وحده

| البند | القاعدة |
|---|---|
| في التنبيهات | لا زر حذف · لا استرجاع · لا سؤال عن الحذف |
| في المؤكد تحديدًا | زر واحد: «متابعة المعالجة»، ثم مدخل للعزل لمن عُزل فعلًا |
| في صندوق العزل | «احتفظ به» · «استرجاع» · **«حذف نهائي»** |
| الحذف الافتراضي | **صفر**. لا شيء يُحذف ما لم يضغط المستخدم الزر داخل العزل |
| المدة | 30 يومًا ثم **تنبيه قبل التنظيف** — والتنظيف أيضًا يتطلب قرارًا |

**لماذا؟** الحذف في لحظة التنبيه قرار متسرّع تحت ضغط؛ وفي العزل قرار هادئ ومُطّلع.
هذا يمنع الندم ويحفظ أدلة.

**قواعد العزل:** مخزن مشفّر يحتفظ بالمسار الأصلي · الملفات المخفية والمعاد تسميتها
تُستعاد إلى موقعها · كل عنصر يحمل شرح خطر بجملة واحدة · استرجاع بضغطة مع التحقق من
الهوية والوجهة وإعادة الفحص · لا حذف تلقائي أبدًا.

### 9.4 عرض المسار (D75)

| البند | القاعدة |
|---|---|
| العرض المحلي | إلزامي — المسار يظهر داخل التنبيه على جهاز المستخدم |
| الشكل | **سطر واحد**، `LTR` معزول، `monospace`، **اقتطاع من الوسط** |
| الأدوات | زر «نسخ المسار» + زر «فتح المجلد» (`explorer.exe /select,`) |
| الاسم مقابل المسار | الاسم في الجملة الرئيسية، والمسار الكامل متاح بالنسخ |
| الإرسال في التقارير | **ممنوع تمامًا** — التقرير يحمل `path_pattern` فقط |

**لماذا الاقتطاع من الوسط؟** لأن الذيل هو ما يحدد الملف، والأول هو ما يحدد الموقع.
اقتطاع الوسط يبقى في سطر واحد ويُظهر الطرفين. التفاف `break-all` داخل واجهة RTL
يشوّه ترتيب المسار ويخرق «جملة واحدة» — والقاعدة الآن واحدة لا ثلاث متعارضة.

### 9.5 الشرح عند الطلب

| القاعدة | التنفيذ |
|---|---|
| الافتراضي: نص قليل | جملة واحدة + اسم الملف |
| مصطلح غامض | يُسطَّر بخط متقطع — إشارة أنه «قابل للسؤال» |
| عند التمرير | سطر واحد فقط |
| عند الضغط | بحث شارح بلغة المستخدم في المتصفح الافتراضي |
| المحرك | حسب اللغة: ar/en/es/de/fr/pt/hi → Google · zh → Baidu · ja → Yahoo Japan · ru → Yandex |
| ماذا يُرسَل؟ | **الاستعلام فقط** — لا اسم ملف، لا مسار، لا بيانات |
| بلا إنترنت | التلميح يعمل محليًا؛ الضغط يُظهر «الشرح الكامل غير متاح بلا إنترنت» |

**لماذا البحث بدل AI داخل التطبيق؟** لأن أي «شرح ذكي» داخل التطبيق يعني إرسال بيانات
إلى طرف ثالث — وهو ما يهدم «صفر تيليمترية».

### 9.6 نظام الأيقونات (D29، D30)

| القاعدة | التفصيل |
|---|---|
| **لا إيموجي في أيقونات الواجهة** | يتبدّل شكله بين ويندوز 10 و11 وبين كل لغة، ويكسر وحدة الهوية |
| المصدر | **SVG sprite داخلي** — ملف واحد، لا طلبات شبكة، لا خط أيقونات |
| النمط | خطّي `stroke` بعرض **1.75** عند 24×24 · نهايات مستديرة · بلا تعبئة |
| اللون | يورث `currentColor` — لا لون ثابت داخل الأيقونة |
| الحجم | ثلاثة فقط: 15 · 18 · 22 بكسل |
| الحركة | لا دوران ولا نبض. التحريك الوحيد: شريط تقدم الفحص |
| RTL | الأيقونات الاتجاهية فقط تُقلب بـ `transform:scaleX(-1)` |

**قاعدة الهجين:** البوابة = من نحن · الدرع = هل أنت آمن الآن. ولا تُستخدم البوابة
للتعبير عن الحالة، ولا الدرع في الشعار. اختبار القبول: لو حذفنا الشعار بقيت كل أيقونة
مفهومة؛ ولو حذفنا الأيقونات بقي الشعار مميزًا.

## 10. البوابات وترتيب العمل

كتابة هذه الخطة ليست إذنًا بتنفيذها. لكل بوابة مدخل وشاهد خروج. إذا غاب الدليل
تُسجَّل الخطوة مفتوحة، ويجوز عمل مستقل لا يتوقف عليها — لكن **لا يجوز إعلان الوظيفة مكتملة**.

### 10.1 بوابات الأساس

| البوابة | تتوقف على | ما يجب إثباته قبل الانتقال |
|---|---|---|
| **K0 · اعتماد النطاق** | المالك وهذه المراجعة | القدرات الست والإضافتان منفصلتان، ومعايير الحالات الأربع مفهومة. لا تنفيذ أو دمج تلقائي |
| **K1 · جدار البيانات** | K0 | عقد مصدر وتحديث قاعدة محلية موثوقة، تطابق الأحكام مع/دون كاش، وعدم تسرّب القياس إلى Public. مرجع G1 وحده ليس القاعدة المطلوبة |
| **K2 · المقيم والمراقبة** | K1 | IPC للمستخدم المخوَّل، تغطية وإبطال صحيحان؛ توقف/تصريف واستئناف واستعادة بعد الفقد، وتجربة NTFS. فصل كلفة العمل B9 عن خمول W2 |
| **K3 · جدار السلوك** | K2 | رصد حقيقي محدود في الحالات الأربع، تحذير الموارد والتنشيط التلقائي قبل الدائم، اختبار الرجوع للخمول وتداخل الأسباب والإيقاف الصريح |
| **K4 · الإنفاذ والاستثناء والعزل** | K2، وأدلة K3 حيث تنطبق | اختبار D45/D46 على Windows، وإيصال منع أو نقل واسترجاع متحقق منه بلا كتابة فوق أصل آخر؛ يعمل الأساس دون إضافتيه |
| **K5 · سطح المكتب** | K2–K4 | الرئيسية والمركز والعزل والإعدادات واللغات العشر تعمل فوق الحالة الحقيقية؛ لا عدادات تدريبية |
| **K6 · قائمة Explorer** | K2 وعرض نتيجة موثوق | نقرة فعلية من مستكشف Windows، فحص محلي للتحديد، نتيجة آمنة عند انقطاع الخدمة، وتركيب/إزالة نظيفان **بلا إضافة متصفح** |
| **K7 · قبول الأساس** | K1–K6 | تثبيت نظيف دون أي إضافة، عمل بلا إنترنت، تراجع وتوقيع واختبارات الجدران والموارد واللغات ومراجعة المالك. لا يُستعاض عن بند أساسي بميزة اختيارية |

### 10.2 بوابة AMSI (D66) — شرط قبول لا ملاحظة

AMSI أساسي في العضوية، ولا تُفتح K7 قبل إثبات ثلاثة أشياء على ويندوز المستهدف:

1. **زمن إضافي ≤15ms لكل سكربت** على عتاد مرجعي معلن.
2. **تغطية إصدارات معلنة** مكتوبة في المواصفة، لا «يعمل عندنا».
3. **اختبار تسجيل المزوّد وإلغاؤه** بلا بقايا، وبلا كسر سكربتات شرعية عند رفض القرار.

فشل أي بند = AMSI يبقى في العضوية ولا يُعلن مكتملًا. لا يُخفَّض المعيار ليُفتح K7.

### 10.3 مساران اختياريان لا يفتحان K7 ولا يحجبانه

| الإضافة | تعتمد على | بوابتها |
|---|---|---|
| **المتصفح** (D48) | IPC وموافقة منفصلة للقراءة | تثبيت وإزالة مستقلان، إيماءة واحدة، لا طلب شبكة للرابط البعيد. هدف Firefox `<100ms` **لم يتحقق** ويبقى مفتوحًا |
| **أتمتة الإصلاح** | احتواء وعزل مثبتان، وصفات موثوقة | معاملة قابلة للتراجع. لا تنقل العزل ولا سلامة الحادثة خارج الأساس |

إذا تعذّر القبول: تُؤجَّل الإضافة، ولا يُخفَّض معيار الأساس ولا معيارها.

### 10.4 حواجز لا تعبر إلا بالدليل

- **حزمة أساسية مكتملة** = K7 مغلقة + R1–R7 مقبولة. لا يغني عنها بناء أخضر.
- **إصدار عام** = توقيع صحيح + Value Manifest + قياس Perf مرفق.
- **«محمي»** لا تُعرض في الواجهة إذا انقطعت التغطية.
- **«مُثبت»** لا تُقال عن سلوك لم يُرصد. الشاهد حدث، لا واجهة.
- **البذرة ليست تغطية** (D104): البذرة المدمجة قاعدة بداية صغيرة موثّقة، ولا يظهر بسببها «محمي»
  ولا نسبة تغطية.

## 11. التقارير والتحديث والإصدار

### 11.1 التقارير — Opt-in فقط

**16 حقلًا إلزاميًا:**

```
sha256, size, header_hash, tail_hash, pe_hash, tlsh,
name_pattern, path_pattern, attributes, behavior_score,
behaviors[], family, app_version, db_version, ts,
ui_lang
```

`ui_lang` آخر حقل، اختياري، مجهول الهوية، غير مربوط بأي معرّف جهاز. غرضه الوحيد:
معرفة أي لغة واجهة تُنتج أكبر عدد من التصنيفات الخاطئة.

**لا يُرسَل أبدًا:** محتوى الملف · المسار الكامل · اسم المستخدم · HWID · لغة النظام ·
المنطقة · البلد · المنطقة الزمنية · أي بيانات شخصية.

**Google Sheets — خمس صفحات:** `Submissions` · `Confirmed_Threats` · `Families` ·
`Trusted_Allowlist` · `Release_Manifest`.

**منطق التكرار:** Apps Script + `LockService` + Queue + معالجة كل 5 دقائق.
عتبة الترقية التلقائية: `Repetition_Count ≥ 3` **و** `Behavior_Score ≥ 85`.

**قيد ملزم:** لا عمود لغة في `Trusted_Allowlist` ولا في `Confirmed_Threats` (§4.8).

### 11.2 التحديث (D90)

- **التطبيق الثنائي: حزمة كاملة، بلا Delta، دائمًا.**
- **بيانات التهديدات وحزم اللغة:** تُحدَّث **كاملة وموقّعة منفصلة** — لا Delta لها أيضًا.
- **الوتيرة:** كل أسبوعين.
- **حزمة طارئة** للتهديدات الحرجة، تُدمج في الإصدار التالي.
- **Value Manifest إلزامي** مع كل إصدار: ما كُسب، وما لم يُحذف، وحجم كل مكوّن.
- **Rollback آمن** لإصدار سابق موقّع.
- **العمر (D113):** سلّم 30/60/90 **ملغى**. لا وضع متشدد، ولا زرّ إقرار، ولا تغيير في سلوك الفحص
  مع العمر. البديل إبلاغ: **شهر الإصدار `YYYY-MM` مطبوع في الرئيسية**، وتذكير **مرة في الشهر** عند
  وجود شبكة، وبعد **ستة أشهر** شارة «يحتاج تحديث» بجانب «محمي» بلون `--warn`. شهر الإصدار يُحقن
  وقت البناء، ولا يُقرأ من طابع ملف يمكن تغييره.
- **قناة البيانات (D106 · D114):** القاعدة **منفصلة** عن البرنامج، بلا سقف حجم، والحاكم ميزانية
  أداء مقيسة. تُنقل بحزمة موقّعة من صفحة الإصدار أو على وسيط، وتُتحقق قبل أي كتابة، ويُعرض تركيبها
  باقتراح هادئ لا تنفيذ تلقائي.
- **الشبكة (D112):** استعمالان لا ثالث — التحقق من إصدار أحدث، وبلاغ عن اكتشاف مؤكد بإذن المستخدم.
  لا قياسات، ولا هوية جهاز، ولا تنزيل أو تثبيت تلقائي.
- **حزم اللغات** لها رقم إصدار مستقل `locales-v1`، وتُشحن بنفس توقيع الإصدار.

**لا استثناء على قاعدة «لا Delta».** أربعة استثناءات مكتوبة في قاعدة مطلقة تعني أن
القاعدة غير موجودة؛ القاعدة الآن واحدة والاستثناءات صارت هي القاعدة نفسها.

### 11.3 مزامنة الأرقام

رقم واحد لكل معيار، في مكان واحد، ولا يُعاد تعريفه في موضع آخر. المرجع في
[الملحق أ](#a1) و[§2](#s2) و[§12](#s12).

## 12. سلوك الوكيل

### 12.1 قبل أي كود

1. **اقرأ §1 ثم §4 ثم §10** ثم المواصفات ذات الصلة وتقرير الشاهد. لا تعامل نموذجًا مخبريًا كمنتج.
2. **اسأل** إذا كان الطلب يخالف قاعدة غير قابلة للكسر.
3. **اقترح خطة** قبل التنفيذ (Plan ← Review ← Code).
4. **لا تنفّذ شيئًا خلال مرحلة ضبط الخطة.** في وضع «تعديل الموجّه» مخرجك ملفات تخطيط ونقاش — لا كود تنفيذي، ولا فتح فرع أو دمج.

### 12.2 أثناء الكتابة

1. لا تخالف الجدران الثلاثة.
2. لا تقلّص القاعدة من أجل الحجم، ولا تُضخّمها من أجل الكمال.
3. لا تستبدل القاعدة المحلية بـAI أو سحابة.
4. لا ترسل محتوى ملفات في التقارير.
5. استخدم التصنيف الثلاثي — لا ثنائي.
6. اكتب اختبارات مع كل ميزة جديدة.
7. وثّق أي قرار معماري **في `docs/decisions.md`**، لا في الموجّه.
8. **لا تستخدم اللغة أو المنطقة أو إعداد الجهاز كإشارة ثقة** — بأي شكل، ولو بدا «حكمة عملية».
9. **لا نص مضمَّن في الكود**: كل نص عبر مفتاح ترجمة.

### 12.3 قبل الـPR

1. **شغّل Golden Set** — لا مراجعة مقبولة بدونه.
2. **قِس الأداء** — لا تجاوز للميزانية.
3. **حدّث `CHANGELOG.md`** والوثائق المرتبطة.
4. **شغّل `i18n-lint`** — صفر مفاتيح ناقصة.
5. **شغّل `doc-lint`** — كل إحالة سليمة وكل رقم بقيمة واحدة (D99).

### 12.4 عند الرفض — تلقائي بلا نقاش

- أي كود يخالف §4.
- أي كود بلا اختبار.
- أي كود بلا توثيق (للميزات الكبيرة).
- أي كود يستخدم اللغة كإشارة تصنيف.
- أي ترجمة تخفّف تحذيرًا أمنيًا في نص أمني.
- أي نص أمني يأتي من مستوى T-B.
- أي تعليق سردي أو إيموجي في الموجّه (D96، D97).

### 12.5 قنوات الاتصال

- لغة الكود والتعليقات: **الإنجليزية**.
- لغة الوثائق: **العربية + الإنجليزية**.
- Commits: إنجليزية (Conventional Commits). PRs: عربية بعنوان إنجليزي.
- مفاتيح الترجمة: إنجليزية، مسطّحة، `domain.component.key`.

**قواعد ملزمة على الجدول (D86، D87):**

### ج.3 مستويات الثقة في الترجمة (D83)

| المستوى | من يترجم | أين يُستخدم |
|---|---|---|
| **T-A** | ناطق أصلي مراجع | كل النصوص، ومنها **كل النصوص الأمنية حصرًا** |
| **T-B** | مجتمع بلا مراجعة | **النصوص غير الأمنية فقط** |
| **T-C** | ترجمة آلية | لا تصل إلى نصوص أمنية إطلاقًا |

**تعريف النص الأمني (ملزم):** تنبيه · زر منع/سماح · تحذير إيقاف · نص عزل · نص حذف
نهائي · نص توقيع أو تحديث. أي منها بلا مراجعة T-A **يُعرض بالإنجليزية**، مع وسم صريح
أن هذه اللغة قيد المراجعة. لا يُعرض نص أمني T-B «بلا إعلان» — هذا ممنوع صراحة.

**اختبار Anti-Bias (D84):** يُختبر التحيّز على **خصائص بنيوية متكافئة** (طول، بنية،
تكرار) مع تطبيع كامل. أي فرق في الدرجة سببه اللغة وحدها = **فشل**. لا يُستثنى اسم
الملف ولا مساره من الاختبار؛ بل يُطبَّعان.

### ج.7 الخصوصية اللغوية

`locale` الجهاز والمنطقة والبلد والمنطقة الزمنية = **بيانات هوية محتملة**. لا تُرسل
أبدًا. `ui_lang` رمز لغة واجهة فقط، مجهول تمامًا. لا يُخزَّن أي سجل يربط ملفًا بلغة جهاز صاحبه.

### ج.8 القرار عند التثبيت

تُعرض اللغات من ملفات محلية موثوقة، مع احترام الاختيار اليدوي على تفضيل النظام.
الاختيار **محلي فقط بلا أي طلب شبكة**. إن كانت لغة النظام غير مدعومة ← الإنجليزية مع
لافتة صغيرة «هل تفضّل العربية؟» مرة واحدة. رفض تنزيل خط أو انقطاع الشبكة لا يحذف
لغة ولا يعطّل فحصًا.

### د.2 الرموز (Tokens)

| الرمز | الاستخدام | فاتح | داكن |
|---|---|---|---|
| `accent` | الهوية وزر الفحص | `#0E7C6B` | `#3FC7B0` |
| `ok` | جدار فعّال | `#157A4B` | `#4ED08A` |
| `warn` | مشتبه / إيقاف | `#8A5200` | `#E0A33A` |

| `focus` | حلقة التركيز | `#0B5FFF` | `#8AB4FF` |
| `surface` / `surface-2` | خلفيات | `#F7F8FA` / `#FFFFFF` | `#1B1D20` / `#24272B` |

**قاعدتان اكتُشفتا بالقياس:**

1. الأخضر الأصلي `#1E8E5A` يفشل كنص (3.90:1)؛ الصحيح `#157A4B`.
2. في الوضع الداكن، نص أبيض على `accent` = 2.10:1 (فشل). الحل: **نص داكن `#0B1416`
   على التعبئة الفاتحة** = 8.89:1. أي أن زر «منع» في الوضع الداكن يحمل نصًا داكنًا —
   وهذا يخالف البديهة، ولهذا يُقاس.

**قاعدة اللون الذهبية:** اللون لا ينقل معلومة وحده. كل حالة = **أيقونة + كلمة + لون**.

### د.6 ترتيب العمل التصميمي (D2)

```
C0 المحددات ← C1 Style Guide ← C2 الحوار النهائي ← C3 بقية اللغات
```

| المرحلة | مخرجها | معيار الخروج |
|---|---|---|
| C0 | جدول مفاتيح + سقوف أطوال + لوحة مقاسة + قواعد RTL | `i18n-lint` يفشل عند التجاوز |
| C1 | `design-system-v1.md` + رموز في الكود | تباين آلي أخضر للوضعين + pseudo-locale بلا كسر |
| C2 | نصوص كل المفاتيح (ar/en) | صفر مفاتيح ناقصة، صفر تجاوز سطرين، مراجعة ناطق أصلي |
| C3 | بقية اللغات | كل لغة تجتاز C2 قبل شحنها — بلا استثناء لـT-B في النصوص الأمنية |

**لماذا المحددات أولًا؟** لأن الأزرار ليست قرارات جمالية بل دالة في النص واللغة:
«منع» 3 أحرف، ونظيرها الألماني `Blockieren` 10 — فرق ×2.3 في العرض. والعربية تقلب
كل بطاقة، واسم ملف لاتيني داخل جملة عربية يحتاج عزل BiDi. بدون المحددات يعمل
المصمم والكاتب في الظلام.

## الملحق هـ — الأداء والقياس

### هـ.1 كيف يُقاس CPU الخمول (D52، D53، D57)

**المعيار:** ≤0.1% متوسطًا على 10 دقائق.
**الموضع:** نسخة Perf حصرًا. رقم البناء العام **مُستنتَج** منها ويُعلَن كذلك.

**البروتوكول — 7 خطوات قابلة للتكرار:**

1. استعادة `baseline-clean` + إعادة تشغيل + انتظار 5 دقائق هدوء.
2. تثبيت نسخة القياس من ملف معروف البصمة (تسجيل SHA-256).
3. قياس الخمول: 10 دقائق، تسجيل RAM/CPU/IO كل ثانية.
4. قياس USB: صورة فلاشة اختبارية (1,000 ملف، 50 تنفيذيًا محاكى) — 3 مرات.
5. قياس الفحص الكامل على Golden Set.
6. قياس AMSI: 200 سكربت (نظيف + EICAR)، تسجيل الزمن الإضافي.
7. تصدير JSON ومقارنة بالبوابات. **أي فشل ← لا إصدار.**

**ضبط الضجيج:** قياسان متتاليان على نفس اللقطة، والفرق >10% ⇒ **يُعاد القياس**
لا يُعتمد. لا قياس أثناء تحديث ويندوز أو فهرسة Defender. تُسجَّل سرعة المعالج وعدد
الأنوية مع كل تقرير — لأن الأرقام بلا عتاد لا معنى لها.

**بيئة المختبر:** Windows 11 Evaluation VM (مجاني، 90 يومًا) · 2 vCPU + 4GB RAM ·
شبكة معطّلة أثناء القياس · لقطة `baseline-clean` تُستعاد قبل كل قياس.

### هـ.2 ما تقيسه نسخة Perf

| المقياس | الوحدة | الحد |
|---|---|---|
| RAM خمول | MB | <20 |
| RAM أثناء فحص USB | MB | ≤50 ذروة، ≤30 إضافة |
| CPU خمول | % | ≤0.1 |
| CPU فحص خلفي | % متوسط | <3 |
| CPU فحص USB | % ذروة | ≤5 |
| زمن استيقاظ USB | ms | <50 |
| زمن P0 | ms | <3000 |
| زمن P1 | ms | <15000 |
| زمن AMSI لكل سكربت | ms إضافية | ≤15 |
| زمن تبديل اللغة | ms | <100 |
| بصمة الذاكرة لكل لغة | MB | ≤3 |
| I/O في الخمول | عمليات/دقيقة | 0 |

**الصيغة:** `odina-perf-{version}-{date}.json` + ملخص Markdown، مرفقة بكل PR وبكل إصدار.

### هـ.3 قواعد نسخة القياس

1. لا تصل للمستخدم العام — تُبنى من ميزة `instrument` وتُشطب قبل الإنتاج.
2. صفر إرسال شبكي — القياس إلى ملف محلي فقط.
3. لا تقيس محتوى المستخدم — أعداد وأحجام وتوقيتات فقط. لا مسارات ولا أسماء ولا بصمات ملفات المستخدم.
4. CI يتحقق أن الإصدار العام لا يحتوي أي رمز قياس (فحص نصي + فحص ثنائي).
5. اختلاف أي بوابة = **فشل إصدار**.

### هـ.4 ما هو مقيس اليوم

**لا شيء على ويندوز.** خط الأساس المتاح في [`docs/perf/baseline/`](perf/baseline/) هو
نقطة بدء معلنة بعتادها، لا دليل قبول. الأرقام في §2 أهداف، وكل رقم يُنشر لاحقًا
يحمل تاريخه وعتاده أو لا يُنشر.

**قيد صريح:** قواعد ClamAV تُشحن كبيانات منفصلة بترخيصها (§4.10)، ولا تُربط شيفرةً.
هذا القيد مكتوب هنا **وفي `LICENSING.md`**، قبل التقديم لا بعده.

## الملحق ز — الانفتاح والتكلفة الصفرية

### ز.1 لماذا الانفتاح ضرورة لا تفضيل

| الادعاء الشائع | الحقيقة |
|---|---|
| «الملفات التنفيذية لا تُقرأ» | يمكن تفكيك أي ملف Rust/C++. الكود المغلق يؤخّر المهاجم أيامًا لا يمنعه |
| «قاعدة البيانات سرّنا» | القاعدة تُشحن إلى جهاز المستخدم؛ أي شخص يستطيع استخراجها |
| «المهاجم سيقرأ شروط الكشف فيتجنّبها» | هذا الخطر الحقيقي الوحيد — ويُعالج بالتصميم لا بالإخفاء |
| «المستخدم سيثق أكثر بالمغلق» | العكس — خصوصًا حين تطلب صلاحيات عميقة على جهازه |

**مبدأ Kerckhoffs:** أمن النظام يجب ألا يعتمد على سرية تصميمه. أي حماية في Odina
تعتمد على «ألا يعرف المهاجم كيف تعمل» هي **حماية غير موجودة**.

**ماذا يطلب Odina فعلًا؟** قراءة كل ملفاتك، مراقبة عملياتك، حماية نفسه من الإيقاف،
والوصول إلى Registry. هذا بالضبط ما تفعله البرمجيات الخبيثة. الفرق الوحيد أن
المستخدم يثق بك — والكود المفتوح هو ما يجعل الثقة قابلة للفحص.

| المفاتيح الخاصة للتوقيع | لا تُوضع في المستودع أبدًا (CI secrets) |
| بيانات المستخدمين والتقارير | لا تُنشر |
| تحليلات أو تيليمترية | لا جمع أصلًا |

> **«صفر ريال» يحسم تلقائيًا أن Odina لا يشحن درايفر نواة.** ومايكروسوفت ترفض تحميل
> أي درايفر غير موقَّع بشهادة EV مدفوعة. ولا طريق ملتوٍ: وضع Test-Signing يطلب من

نتعايش معها كطبقة ثانية، ونُعلن ذلك في README.

**إن تغيّرت الميزانية لاحقًا:** EV يبقى مؤجّلًا حتى بوابة G4 في [الملحق ح](#a8)،
ويحتاج قرار مالك جديدًا في `decisions.md` — لا يُستنتج من هذا البند.

1. **لا قياس ويندوز.** لا رقم أداء في هذا الملف مُثبَت على منصة حقيقية.
2. **حدود المراقبة وInjec** — معروفة، ويُقاس أثرها في K2.
3. **AMSI وWDAC** — العضوية محسومة، والإثبات لا. K7 لا تُفتح بادعاء.
4. **جدار السلوك** — أساسي في العضوية، غير مكتمل في التنفيذ. أُعلن، لا أُخفي.
5. **الأسئلة العشرة المفتوحة** في `decisions.md` §3 — لن يُملأ أي منها افتراضًا.

**عند غياب دليل أو تعارض جديد:** سجّل السؤال وموضعه في `decisions.md`، وارجع إلى
المالك. لا تملأ الفراغ بميزة ولا بوعد شحن.
