# التوقيع المجاني — كيف يُشحن Odina بلا أن يدفع أحد ريالًا

> **الحالة:** ✅ الخيارات محسومة — 2026-11-15
> **المرجع:** `docs/roadmap.md` E1–E3 · `LICENSING.md` · §26.6 (user-mode بلا درايفر)
> **الغرض:** أن يرى المستخدم **ناشرًا موثوقًا** لا «ناشر غير معروف» — بتكلفة **0 ريال**.

---

## 1. المشكلة في سطر واحد

بدون توقيع، يظهر تحذير Windows SmartScreen: **«Windows حماية جهازك»** و«ناشر غير معروف». وهذا أخطر من إنذار كاذب واحد، لأنه يجعل المستخدم يتعلّم أن **يتجاوز** التحذير — وهو أفضل خدمة يقدّمها أي منتَج لمن يريد إصابته.

**والمشكلة الحقيقية ليست التقنية بل السعر:** الشهادات التجارية تبدأ من ~$200/سنة. والقاعدة عندنا **0 ريال**، لا تُفاوَض.

## 3. الخيار 1 — SignPath Foundation (الأساسي)

### 3.1 لماذا هو المناسب لنا بالضبط

لأن شرطه الأول هو **ترخيص معتمد من OSI بلا ترخيص تجاري مزدوج** — وهذا حرفيًا ما اخترناه: AGPL-3.0-or-later للنواة، MIT للأدوات (D7 · D31). أي أن الرخصة التي اخترناها لحماية المستودع من الاحتكار المغلق هي نفسها التي **تفتح** باب التوقيع المجاني.

### 3.2 الشروط كما هي — والوضع عندنا

| الشرط | حالتنا |
|-------|--------|
| ترخيص OSI بلا ازدواج تجاري | ✅ AGPL-3.0-or-later |
| مستودع عام | ✅ GitHub |
| التوزيعات تُحمَّل مجانًا | ✅ GitHub Releases بلا مقابل |
| لا سلوك خبيث، لا التفاف أمني | ✅ مكافح، لا يكسر حماية |
| مشروع **نشط** | ✅ التزامات يومية |
| **صدر منه إصدار قابل للتوقيع فعلًا** | ⏳ **هذا هو الشرط الوحيد غير المكتمل** |
| وظائفه موثّقة | ✅ `README.md` + `docs/spec/` |
| سياسة توقيع منشورة على الموقع | ⏳ تُكتب عند التقديم (مرفقة أدناه) |
| أدوار Author / Reviewer / Approver معرّفة | ✅ كلها لك الآن (مشرف واحد) |
| MFA على GitHub لكل عضو | ⚠️ **يجب تشغيله قبل التقديم** |

### 3.3 لماذا التقديم الآن **مؤجّل** — والصدق في السبب

SignPath تطلب «إصدارًا صدر فعلًا في صيغة قابلة للتوقيع». ولا يوجد لدينا EXE بعد — لأن بوابة §36.4 (R1–R7) **تمنع** بناء أي EXE قبل اكتمالها. وهذا اختيارنا لا نقص عندنا، لكنه يعني أن التقديم الآن **سيرفض**.

**الترتيب الصحيح:**

```
B · C · D مكتملة  →  R1–R7 مكتملة  →  أول EXE غير موقّع + بصمة SHA-256 معلنة
                                      ↓
                        تقديم SignPath (3–5 أيام عمل)
                                      ↓
                        أول EXE موقّع = بوابة G3
```

وبين البناء الأول والتوقيع، التوزيع يكون **ZIP محمول + ملف بصمات** على GitHub Releases. لا «علبة مثبّت» بلا توقيع — لأن التحذير الذي يُتعلَّم تجاوزه لا يُنسى.

### 3.4 ما سيُوقَّع بالضبط

- المثبّت (`Odina-Setup-x.y.z.exe`) و/أو حزمة MSIX؛
- كل التوقيع يحدث **على عدّاد CI** من نفس الملف الذي بُني، لا يُعاد بناؤه؛
- **لا مفتاح خاص في المستودع ولا في أسرار CI** — SignPath تحتفظ به في HSM؛
- طابع زمني (timestamp) على كل توقيع، فتبقى البصمة صالحة بعد انتهاء الشهادة.

## 4. سياسة التوقيع — النص الذي سيُنشر على الموقع

> يُنشر قبل بدء التوقيع، لأن SignPath تطلب سياسة منشورة على صفحة المشروع.

**العربية:**

> **سياسة توقيع الشيفرة — Odina**
>
> نُوقّع ملفات Windows التنفيذية فقط، ولا نُوقّع أي شيء لم يُبنَ من هذا المستودع.
>
> - **البناء:** كل توقيع يحدث على عدّاد GitHub Actions من الالتزام المُعلَن في `CHANGELOG`؛ لا بناء محلي، ولا إعادة بناء قبل التوقيع.
> - **المفتاح:** لا نحتفظ بأي مفتاح توقيع. المفتاح في HSM لدى SignPath Foundation، ولكل عملية توقيع موافقةُ مشرف صريحة.
> - **ما يُوقَّع:** المثبّت وحزمة MSIX فقط.
> - **ما لا يُوقَّع:** قواعد البصمات (تُوقَّع بـEd25519 منفصل)، وأي أداة داخل `tools/` لأنها MIT تُوزَّع كنص مصدري.
> - **التحقق:** بصمة SHA-256 لكل ملف تُنشر في صفحة الإصدار قبل التوقيع وبعده.
> - **الإلغاء:** إن بُني إصدار من شيفرة غير مُراجَعة، نُلغيه ونُعلن الإلغاء قبل أي شيء آخر.

**English (required by the program):**

> **Code signing policy — Odina.** Only Windows binaries built from this repository are signed. Builds run on GitHub Actions from the commit named in the release notes; the signing key is held in SignPath Foundation's HSM and every signing request requires explicit maintainer approval. Signed: the installer and the MSIX package. Not signed: signature databases (Ed25519, separate key) and `tools/` (MIT, distributed as source). A SHA-256 for every artefact is published on the release page. If a build is ever produced from unreviewed code, the certificate is revoked and the revocation is announced first.
>
> *Free code signing provided by SignPath.io, certificate by SignPath Foundation.*

**ملاحظة ملزمة:** الجملة الأخيرة **شرط تعاقدي** إنشاءً — تُنشر حرفيًا على صفحة التنزيل، لا تُترجم ولا تُحذف.

## 5. الخيار 2 — متجر Microsoft (MSIX)

**التكلفة: 0.** حساب المطوّر الفردي مجاني (منذ 10 سبتمبر 2025، والحساب التجاري مجاني أيضًا في المسار الجديد منذ 2026) — والشرط الوحيد هو **تحقق هوية**: صورة بطاقة حكومية + سيلفي.

**والميزة الحاسمة:** حزم MSIX **يُعيد Microsoft توقيعها** بعد الاجتياز — أي **لا تحتاج شهادة خاصة بك**.

**والقيد الذي يجب قوله:** إعادة التوقيع هذه **لا تشمل EXE/MSI**، بل MSIX فقط. فإن أردنا توزيع EXE خارج المتجر، يبقى SignPath هو الطريق.

**وحدّ ثالث:** المتجر يراجع التطبيق (سياسات + اختبار). مكافح يوقف تنفيذ ملفات قد يُسأل عن ذلك — لكن Odina **لا تعزل إلا بعد قرار المستخدم** أو في حالة ≥0.99، وهذا موقف يمكن الدفاع عنه بوضوح في نموذج التقديم.

**وميزة عملية للمستخدم اليمني تحديدًا:** التحديث التلقائي من المتجر يعني **لا تنزيل يدوي ولا إعادة تثبيت** على اتصال بطيء.

## 6. الخيار 3 — الموقّع ذاتيًا (للتجربة فقط)

مجاني تمامًا، ويُولَّد بأمر واحد على ويندوز (`New-SelfSignedCertificate`). **ولا يُوزَّع للمستخدمين**، لأن:

- Windows لا يثق به افتراضيًا؛
- المستخدم يرى نفس «ناشر غير معروف»، وأسوأ: تحذيرًا قد يبدو مشابهًا؛
- ولا يمرّ SmartScreen.

**فائدته الحقيقية واحدة:** اختبار أن المثبّت **يُوقَّع ويُتحقَّق** تقنيًا في CI قبل أن تُفتح بوابة G3 — أي نختبر **الأنبوب** لا الثقة.

## 9. الحقيقة الأخيرة

**التوقيع ليس ثقة.** التوقيع يقول «هذا الملف جاء من صاحبه ولم يُغيَّر في الطريق». ولا يقول شيئًا عن **ما يفعله** البرنامج بك.

ولهذا Odina يبني الثقة بثلاثة أشياء لا رابع لها: **مصدر مفتوح** يُقرأ · **صفر تيليمتري** يُقاس · و**لا حذف** إلا بمكان واحد معروف. والتوقيع المجاني هو آخرها شأنًا — مهم، لكنه ليس الأول.
