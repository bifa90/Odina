# إلى مالك المشروع: نتيجة اختبار G1/B6

**القرار: مسار الكشف يعمل على الملف المعياري، لكن G1 بملف مُنزَّل من EICAR لم يُعتمد بعد.** قبل التغيير (`4d6afe2`) كان كلٌّ من `scan` و`check` يمرّر `known_bad=false`، وكان `selftest` يختبر البصمة في الذاكرة فقط. في بناء `c2b2f69` صارت قراءة الملف، والمطابقة، واستدعاء V5 مشتركة بين الأمرين. لم تتغير الأوزان أو العتبات أو أولوية الـveto.

## ماذا حدث عند تشغيل الملف التنفيذي؟

هذه **نتائج تشغيل على لينكس**، لا توقعات من اختبار وحدة. فُحص JSON الناتج أيضًا بمحلّل مستقل. الرمز 2 في صف التنبيه نتيجة كشف متوقعة، وليس خطأ في الأمر.

| المدخل | `odina scan` العام | `odina check` مع `instrument` |
|---|---|---|
| ملف مؤقت عادي الاسم، فيه المتجه المعياري نفسه المستخدم في اختبارات المشروع (68 بايتًا، **لم يُنزّل**) | «مؤكد»، `known_bad=true`، `veto=KnownBad`، `interrupts=true`، خروج **2** | ملف واحد، `confirmed=1`، `unreadable=0`، وتقرير `odina-report/v1` واحد ببصمته؛ خروج **2** |
| `tests/fixtures/safe/`، عشرون ملفًا مؤلفة محليًا: 8 نصوص و6 Rust و6 JSON | **20/20** بصمة كاملة مختلفة، `clean` للجميع، **0 تنبيهات، 0 متعذرة القراءة**، خروج **0** | `files=20`، `bytes=1276`، `clean=20`، `unreadable=0`، `read_errors=0`، `truncated=false`، `reports=[]`، خروج **0** |

- **بصمة المدخل الموجب:** `275a021bbfb6489e54d471899f7db9d1663fc695ec2fe2a2c4538aabf651fd0f`. في مجلد مؤقت جمع المتجه والعشرين السليمة طبع `scan`: «21 ملفًا · 1 يستدعي تنبيهًا · 0 تعذّرت قراءته»، وأظهر «مؤكد» أمام الملف الصحيح.
- `database_present=true` في JSON المحلي يعني أن المرجع المدمج `g1-eicar-only-1` حاضر، **لا** أن هناك قاعدة تهديدات إنتاجية. يظهر المعرّف نفسه في `db_version` للتقرير المصدَّر. لا اسم أو مسار خام في ذلك التقرير، ولا حقول مضافة للمخطط. البناء العام يرفض `check` ولا يكتب ملف قياس.
- [مرجع النواة](../../crates/odina-core/src/g1_reference.rs) يقارن البصمة **الكاملة** فقط. اختبار مستقل يرفض الملف بعد تغيير بايت واحد، ويرفض البصمة الكاملة الغائبة ولو طابق الرأس والذيل. حتى الملف السليم المسمّى `eicar.txt` لا ينبّه. هذه أمثلة لمسار القرار، **ليست قياس حساسية أو FPR**.

## الإثبات الناقص وطريقة إعادته

فشل اتصال TLS بمضيف الملف الرسمي وبموقع EICAR الرسمي (`curl` خرج بـ **35**، `HTTP 000`، صفر بايت من الملف). لم نستخدم مرآة ولا عيّنة حيّة. تطابق SHA-256 يثبت البايتات، لكنه لا يثبت أننا حصلنا على الملف من الناشر. لذلك لا نضع علامة نجاح أمام شرط التنزيل الرسمي.

لإكمال الشرط: في بيئة الاختبار المعزولة، استخدم النسخة النصية غير المضغوطة من **صفحة EICAR الرسمية فقط**، خارج شجرة Git. لا تشغّل الملف ولا تعطّل Defender؛ إن حجزته حماية الجهاز، سجّل العائق. اضبط `ODINA_G1_EICAR` إلى **مساره المطلق**. أوامر لينكس التالية من جذر المستودع؛ ملفات القياس تبقى خارج مجلد الفحص. لا تُرفق العيّنة أو المخرجات ذات المسارات عند مشاركة النتيجة.

```bash
set -eu
: "${ODINA_G1_EICAR:?set this to the official file outside Git}"
export ODINA_G1_EICAR
hash=275a021bbfb6489e54d471899f7db9d1663fc695ec2fe2a2c4538aabf651fd0f
test "$(wc -c < "$ODINA_G1_EICAR")" -eq 68
actual=$(sha256sum < "$ODINA_G1_EICAR"); test "${actual%% *}" = "$hash"

cargo test --locked -p odina-cli --test g1
cargo test --locked -p odina-cli --test g1 --features instrument

umask 077
out=$(mktemp -d)
expect_exit() { want=$1; shift; rc=0; "$@" || rc=$?; test "$rc" -eq "$want"; }
cargo build --locked -p odina-cli --target-dir "$out/public"
expect_exit 2 "$out/public/debug/odina" scan "$ODINA_G1_EICAR" --json
expect_exit 0 "$out/public/debug/odina" scan tests/fixtures/safe/
cargo build --locked -p odina-cli --features instrument --target-dir "$out/check"
expect_exit 2 "$out/check/debug/odina" check "$ODINA_G1_EICAR" --out "$out/positive.json"
expect_exit 0 "$out/check/debug/odina" check tests/fixtures/safe/ --out "$out/safe.json"
```

[اختبار التكامل](../../crates/odina-cli/tests/g1.rs) يستدعي الملف التنفيذي الفعلي بلا شبكة. إن **غاب** المتغير تمامًا، يكتب المتجه المعياري مؤقتًا لأجل اختبار الانحدار؛ وإن عُيِّن لملف مفقود أو غير مطابق **يفشل** بدل الرجوع إلى المتجه. لا يعتبر نجاح الحالة الأولى تنزيلًا رسميًا.

## البناء والحدود

| التحقق | النتيجة |
|---|---|
| `cargo fmt --all -- --check` | نجح في شجرة العمل |
| `cargo build --locked` في شجرة العمل بقفلها الأصلي | تعذّر محليًا: خطأ TLS رقم 35 عند جلب إعدادات الفهرس من `index.crates.io`؛ لم نعدّل القفل أو نضع مسارات بديلة فيه |
| تشغيل لينكس المحلي المبين أعلاه | نسخة مؤقتة من المصادر نفسها وRust/Cargo 1.85، مع تبعيات upstream بالإصدارات العشرة نفسها وقفل مؤقت لمساراتها. نجح `cargo build --locked` فيها بنسختيه، و`cargo test --workspace --locked` (**142**) و`cargo test -p odina-cli --features instrument --locked` (**24**، فيها اختبارات مكررة من البناء الأول) |
| Clippy المحلي | نجح للبناءين في النسخة المؤقتة: `cargo clippy --workspace --all-targets --locked -- -D warnings` ثم `cargo clippy -p odina-cli --features instrument --all-targets --locked -- -D warnings`. نجح كذلك فحص شجرة الربط العامة وفحص الأنواع لهدف Windows MSVC؛ الأخير ليس تشغيلًا على ويندوز |
| قفل المستودع في CI (`c2b2f69`، طلب المراجعة #12) | **نجح على Windows وUbuntu**: [سجل Rust](https://github.com/bifa90/Odina/actions/runs/44485362461) يشمل `cargo build --workspace --locked` والاختبارات وClippy `-D warnings` للبناءين. [بوابات المشروع 14/14](https://github.com/bifa90/Odina/actions/runs/44485362604) خضراء أيضًا. هذا دليل القفل الأصلي؛ لا نستعيض عنه بالقفل المحلي المؤقت. لم يتغير سير CI في هذه المهمة |

**قرار المالك المطلوب:** إعادة الحالة الموجبة من المصدر الرسمي وتأكيد نتيجتها في البناءين قبل اعتماد G1. لا نحتاج ملفًا من جهاز شخصي ولا عيّنات إضافية. بعد الاعتماد تكون الخطوة التالية **B9 كاملة قبل B1/Tauri أو C/USB**: بناء معلوم، جهاز i7-8550U والمجلد نفسيهما، ومتوسط أقل من **3% من نواة واحدة**. [اختبار المقام والأرقام المقارنة](../perf/baseline/README.md)؛ بقي القياس الفعلي الأخير **27.99% (فشل)**.
