# Odina — وثيقة الحماية v1 (Protection Policy)

> **الحالة:** ✅ معتمدة — 2026-11-16
> **المرجع الأعلى:** `docs/odina-agent-prompt-v18.md` §0 و§3 و§7 و§8 و§24.5. البنود أدناه شروط للمنتج، وليست ادعاء بأن نسخة CLI تمنع أو تعزل اليوم.
> **القاعدة:** إن تعارضت هذه الوثيقة مع الموجّه فالموجّه يحكم. وإن تعارض الموجّه مع **§2.1 أسس الثقة** فالأخيرة تحكم.

هذه ليست وثيقة تسويقية. هي **سلوك Odina المحدَّد** مقابل كل حالة. كل سطر هنا قابل للتحويل إلى اختبار.

---

## 1. المبدأ الحاكم

> **في الأساس:** نحتوي الإصابة، نحمي الأصل، نتيح العزل القابل للاسترجاع ونتحقق من زوال الخطر. لا حذف تلقائي. **الإنقاذ الآلي والصيانة إضافة اختيارية**؛ عند اختيارها يُطهَّر ما يمكن إنقاذه بأمان قبل العزل (D47/D51).

وهذا ليس تفضيلًا تصميميًا — بل قرار مالك المشروع الملزم (§8.2.2، D26):

| # | القاعدة | الاختبار |
|---|---------|----------|
| P1 | **لا زر «حذف» في أي تنبيه** — بأي حال — ولو كان التهديد مؤكدًا | فحص واجهة: صفر أزرار حذف خارج العزل |
| P2 | **الحذف حصريًا داخل صندوق العزل** | لا مسار كود يحذف ملفًا من سياق تنبيه |
| P3 | **لا حذف تلقائي أبدًا** — 30 يومًا ثم **تنبيه قبل التنظيف** | اختبار: انتظار 31 يومًا لا يحذف شيئًا |
| P4 | **منع التشغيل ثم متابعة الحادثة**؛ عزل قابل للاسترجاع إذا تعذر الإنقاذ الآمن، حتى بلا كتالوج إصلاح | لا نعرض «مُنع» أو «عُزل» قبل إيصال التنفيذ أو النقل |

> **السبب:** الحذف لحظة التنبيه قرار **متسرّع تحت ضغط**. وفي العزل قرار **هادئ ومُطّلع**. والفرق بينهما هو الفرق بين ندم لا رجعة فيه، وقرار يمكن التراجع عنه.

## 2. الجدران الثلاثة

الجدران الثلاثة أساسية. جدار البيانات والاستباقية فعّالان افتراضيًا ما دامت الحماية عاملة. الجدول يصف **هدف التصميم**، والأرقام تقديرات كلفة لا نتائج قياس. ترتيب تقييم ملف لا يقرر وحده متى ينشط الرصد السلوكي للجهاز.

| # | الجدار | متى يعمل | التكلفة | ما يُخرجه |
|---|--------|-----------|---------|------------|
| **1** | **قاعدة بيانات الملفات** | أولًا دائما — قبل أي شيء | ~0.2 ms/ملف (Bloom) | بصمة مطابقة أو احتمال |
| **2** | **الفحص السلوكي** | خامل بين المهام إلا إذا اختار المستخدم الرصد الدائم؛ نشاط مؤقت وفق §2.2 | تُقاس الزيادة مستقلةً في K3 | أدلة سلوكية محلية في النطاق المعني |
| **3** | **الحماية الاستباقية** | قبل كتابة محمية أو نشاط محدد في §2.3.1 | ~0.05 ms/حدث | منع الكتابة قبل وقوعها |

**قاعدة التسلسل:** لا نعيد تحليل ملف سلوكيًا لمجرد تكرار فحص حسمه الجدار الأول. عتبة التصعيد في [مواصفة التقييم](scoring-spec-v1.md) تخص **الملف**؛ ليست شرطًا مسبقًا لتشغيل الجدار أثناء فحص مباشر أو مهمة سريعة أو لحماية الجهاز عند الخطر. لا يُستدعى إنفاذ الجدار الثالث إلا لنشاط منطبق. ولا نُشغّل العينة كي نستدعي جدارًا.

### 2.1 الجدار الأول — قاعدة بيانات الملفات

| المرحلة | البنية | السقف |
|---------|--------|-------|
| A | **Bloom filter** للبصمات المعروفة | 3 مليون بصمة × 1.44 بايت ≈ **4.3 MB** — false positive < 0.1% |
| B | **Hash table** للتحقق النهائي | لا تُقرأ إلا عند إيجابية Bloom |
| C | **TLSH** للقرابة الضبابية | يُحسب فقط عند تطابق الحجم ±50% |

**الترشيح المتتالي:** Bloom أولًا (رخيص) → ثم مطابقة دقيقة (متوسط) → ثم TLSH (غالٍ). **لا يُحسب TLSH أبدًا إن لم يمرّ الملف من Bloom.**

### 2.2 الجدار الثاني — الفحص السلوكي

**غير مكتمل، لكنه إلزامي في التثبيت.** يبقى خاملًا دون أسباب؛ اختيار الرصد الدائم للمستخدم وحده بعد إبلاغه **أنه قد يستهلك موارد** و**أنه ينشط تلقائيًا عند الخطر حتى دون الدائم**. يستطيع إلغاء الدائم دون إزالة الجدار.

**أسباب مؤقتة:** (1) فحص ملف مباشرةً بطلب المستخدم؛ (2) إصابة الجهاز؛ (3) إدخال عنصر خطر مثل فلاشة أو قرص قابل للإزالة؛ (4) الفحص السريع للملفات المفتوحة والنقاط الخطرة. لا يُصنّف جهاز جديد مصابًا لمجرد وصوله. تُحرَّر المهمة عند اكتمالها أو إلغائها الآمن؛ لا يزول سبب الإصابة حتى التحقق. لا يعود الجدار خاملًا حتى تزول كل الأسباب، إلا إذا كان الدائم مختارًا فيبقى وفق التفضيل. الإيقاف الصريح النافذ أسبق من الجميع؛ إسكات التنبيهات لا يمسّ التفضيل أو الأسباب. جدول الأحداث والحدود في §3.1 من [الموجّه](../odina-agent-prompt-v18.md).

الهدف رصد نشاط محلي منطبق (مثل بدء عملية وكتابة لاحقة في موضع بدء التشغيل)؛ لا تسجيل شامل لأوامر المستخدم ولا تحليل سحابي. لا يُحسب `Imports/Strings` في ملف ساكن أو تحقق SHA-256 من ملف عملًا لهذا الجدار. سياسة **تقييد** محرك سكربت من عمل الجدار الثالث، لا دليل تنشيط للجدار الثاني.

### 2.3 الجدار الثالث — الحماية الاستباقية

المطلوب من موصل ويندوز منع الكتابة المحمية **قبل** حدوثها. فحص السكربت ومنع التشغيل ومسارات السجل والشبكة نقاط إنفاذ مختلفة؛ قرار النواة وحده لا يحجب عملية في النظام.

| المسار المحمي | لماذا |
|----------------|-------|
| `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup` | الإقلاع التلقائي |
| `HKCU\...\CurrentVersion\Run` | الإقلاع التلقائي |
| `%SystemRoot%\System32\drivers\etc\hosts` | توجيه التصيّد |
| `%ProgramData%` (جذور فقط) | التثبيت الصامت |
| ملفات `.lnk` في جذر أي جهاز | قلب هجوم USB |

قائمة المسارات مغلقة. أمّا **الأنشطة** التي تُعرض مفردة في «الحماية الاستباقية» فتخضع للجدول التالي، لا لقاعدة عامة من قبيل «أوقف كل خدمات ويندوز».

#### 2.3.1 الأنشطة التسعة واحتواء الإصابة (D46)

التقسيم **3 / 4 / 2** قرار المنتج بناءً على ملف المالك «الحماية الاستباقية.txt». الأثر وسهولة إساءة الاستخدام أدناه **تقديران من المرفق** وليسا نسب انتشار مقيسة أو تصنيفًا معتمدًا من MITRE. فئة القرار تراعي أيضًا أثر منع استخدام شرعي؛ «اختياري» لا تعني أن اتصال RDP أو سكربتًا بعينه آمن.

| النشاط المطابق (لا البرنامج كله) | الأثر / سهولة إساءة الاستخدام | عند تشغيل الحماية بلا إصابة |
|---|---|---|
| بدء cmd أو PowerShell أو mshta من Word أو Excel | حرج / عالية جدًا | **منع تلقائي**، لا سماح من هذا الصف |
| إنشاء اشتراك أحداث WMI دائم من مصدر غير موثوق | حرج / متوسطة | **منع تلقائي**؛ لا يمس استعلامات WMI العادية |
| استخدام mshta أو certutil أو regsvr32 مع مدخل غير موثوق من مجلد مؤقت أو الإنترنت | عالٍ جدًا / عالية | **منع تلقائي** لهذا السياق فقط |
| إنشاء مهمة مجدولة أو تعديلها | عالٍ / متوسطة | مسموح افتراضيًا؛ **يُنصح بالمنع** |
| تغيير تسجيل COM الخاص بالمستخدم | عالٍ / متوسطة | مسموح افتراضيًا؛ **يُنصح بالمنع** |
| إضافة إدخال إلى Run أو RunOnce أو تغييره | عالٍ / عالية جدًا | مسموح افتراضيًا؛ **يُنصح بالمنع** |
| إنشاء خدمة أو تثبيت تعريف | حرج / تتطلب خبرة متقدمة | مسموح افتراضيًا؛ **يُنصح بالمنع**؛ لا نوقف الخدمات العاملة |
| اتصال وارد جديد للمشاركة أو سطح المكتب البعيد (SMB/RDP) | عالٍ / متوسطة | مسموح من هذه الطبقة؛ **المنع اختياري**، ولا يُفتح منفذ |
| تشغيل سكربت عادي ‎`.js` / `.vbs` / `.wsf` عبر WSH | متوسط / عالية | مسموح من هذه الطبقة؛ **المنع اختياري**، وتبقى فحوص السكربت |

**أولوية القرار عند مطابقة نشاط:** إيقاف الحماية الصريح ← لا إنفاذ من هذه الطبقة؛ وإلا فالاحتواء ← المنع التلقائي ← منع المستخدم ← متابعة الفحوص الأخرى. إذا طابق الحدث أكثر من نشاط يكفي منع أحدها. السماح هنا لا يُضعف جدار ويندوز أو فحص التوقيع أو حكم الملف، ولا يضيف استثناء D45. استثناء WSH المحفوظ لا يتغلّب على منع نشاطه ولا يمتد وقتُه أثناء الاحتواء.

| الحدث | أثره |
|---|---|
| فحص عادي أو اشتباه فقط | لا احتواء شامل |
| تأكيد إصابة أثناء فحصها والحماية تعمل، ولو أُسكتت التنبيهات | **منع الأنشطة التسعة مؤقتًا**. يحتفظ منسّق المعالجة بمعرّف مستقل لكل مهمة؛ تكرار الكشف في المهمة نفسها لا يضيف منعًا ثانيًا. إصابة جديدة لا تشملها تلك المعالجة تأخذ مهمة مستقلة |
| اكتمال تقييم الجدران المنطبقة ثم تحييد الخطر | تتبع الحادثة §2.4. تبقى الأنشطة ممنوعة حتى التحقق، سواء اختار المستخدم الأتمتة أم لا |
| فشل خطوة أو إلغاؤها، أو وصول إتمام قديم/خارج الترتيب | يبقى المنع؛ لا يُقبل إلا نجاح الخطوة المنتظرة للمهمة نفسها |
| نجاح الإصلاح والتحقق النهائي لآخر مهمة مفتوحة | يُرفع المنع المؤقت فقط. لا نكتب إعدادات بديلة ولا نعيد الجميع إلى «مسموح»؛ تعود **اختيارات المستخدم نفسها** |
| الحماية موقوفة أصلًا بقرار المستخدم (§4.2) | لا يبدأ احتواء ولا يفعّل إتمامٌ متأخر الحماية. إسكات التنبيهات (§4.1) ليس إيقافًا |

**حدّ التنفيذ:** `odina-core::proactive` يحسم القرار، والمعاينة تحاكي مهمة واحدة. لا يعمل حاليًا موصل ويندوز يلتقط هذه الأحداث قبل وقوعها أو ينفّذ المنع والتنظيف والإصلاح. `odina scan` للقراءة فقط. في الخدمة المستقبلية يلزم حفظ المهام غير المحسومة في سجل موثوق مستقل عن التفضيلات واستعادتها قبل الإنفاذ عند الإقلاع؛ إغلاق النافذة ليس نجاح إصلاح. لا يتطلب هذا القرار إيقاف خدمة عاملة، أو إنهاء مفسّرات الأوامر جماعيًا، أو تسجيل أوامر المستخدم.

### 2.4 المعالجة بعد الكشف (D47)

التأكيد يستدعي الاحتواء ولا يقرر وحده مصير الملف. في الأساس دون إضافات: تحييد الخطر، حفظ الأصل، وعزل مسبب قابل للاسترجاع أو معالجة يدوية موثقة يعقبها تحقق. مع أتمتة الإصلاح المختارة: وصفة موثوقة لنسخة مرحلية ثم إصلاح وتحقق؛ البرمجية المستقلة أو ما تعذّر إنقاذه يُعزل ولا يُحذف. تعذّر النقل لا يُحسب عزلًا، ونجاح ملف واحد لا يغلق الحادثة. [عقد المكوّن وحدّ التجربة](repair-component-v1.md).

## 3. التصنيف — ثلاثة مستويات، لا اثنان

| المستوى | التقرير | سلوك الواجهة |
|---------|---------|---------------|
| 🟥 **مؤكد** | كشف قاعدة معروفة أو ≥ 99% | منع التشغيل وبدء المعالجة + زر واحد: «متابعة المعالجة»؛ الإسكات يؤخر العرض لا العمل |
| 🟨 **مشتبه بشدة** | 80–98.9% | إيقاف مؤقت + قرار **فوري** من المستخدم (زرّان) |
| ⬜ **مشتبه** | 50–79.9% | منع مؤقت + فحص عميق + قرار لاحق |

**ما دون 50% لا يُعرض على المستخدم إطلاقًا.** يُسجَّل في Ring Buffer ويُراقب تكراره. **عرض ما دون العتبة = إزعاج = فقدان ثقة.**

**والتصنيف لا يعتمد على اللغة.** اسم ملف عربي أو صيني لا يرفع الوزن ولا يخفضه (§3.8). القيمة من **بنية النمط وتكراره**، لا من لغوي محتواه.

## 4. المستويان: إسكات التنبيهات · إيقاف الحماية

> **قرار مالك المشروع (2026-11-16) — يُلغي «لا يوجد Disable»:** *«المبدأ هو الوضوح والمرونة، وليس تقييد وإزعاج المستخدم — مع وضع المسؤولية على المستخدم فيما يتخذه، وتنبيهه.»*

المستخدم يملك جهازه. والمنتج الذي يُقرر عنه **يُعطَّل**، والمنتج الذي **يُخبره ويتركه يقرر** يُحترم. فصار هناك مستويان **منفصلان بوضوح تام**، لا مستوى واحد بأسماء متعددة.

### 4.1 المستوى الأول — إسكات التنبيهات (Pause)

| البند | القرار |
|-------|--------|
| **ما يتوقف** | **التنبيهات فقط** — لا نافذة، لا إشعار، لا صوت |
| **ما يستمر** | **سياسة الجدران الثلاثة لا تتغير.** يستمر الفحص والمنع المنطبقان؛ لا يتحول الخامل إلى دائم، ولا ينشأ إذن لأتمتة الإصلاح |
| **ملف مصاب أثناء الإسكات** | **يُمنع من التنفيذ ويُعالَج بمسار §2.4 المعتاد** — ونتذكر ما حدث ونعرضه **دفعة واحدة عند انتهاء المدة** (قرار مالك المشروع 2026-11-16) |
| **التطبيق** | **لم يُغلق.** يعمل، يفحص، يمنع، **ولا يسأل** |
| **المدد** | 10 دقائق · 30 دقيقة · ساعة · **حتى إعادة التشغيل** |
| **الإرجاع** | تلقائي عند انتهاء المدة · أو يدوي بضغطة |
| **الشريط الظاهر** | «التنبيهات متوقفة مؤقتًا · الحماية تعمل» |
| **عند العودة** | ملخص واحد: أُصلح · عُزل · قيد المعالجة، مع مدخل إلى المعالجة. **دفعة واحدة، لا نافذة لكل ملف** |

**وهذا هو الفرق الجوهري عن الإيقاف:** في Pause **لا يُتخذ قرار إضافي** — يمنع ويعالج، لكن **بصمت**. فالمستخدم لم يطلب «لا تحمِني»، بل طلب «أخبرني لاحقًا».

### 4.2 المستوى الثاني — إيقاف الحماية (Turn protection off)

| البند | القرار |
|-------|--------|
| **ما يتوقف** | **كل شيء.** لا فحص، لا منع، لا تنبيه. الخدمة تبقى مشغّلة لكن **خاملة** |
| **التحذير** | شاشة حمراء صريحة قبل التنفيذ (§4.3) |
| **المدد** | 30 دقيقة · ساعة · **حتى نهاية ساعة الذروة** · حتى إعادة التشغيل |
| **لا زر «دائم»** | أقصى مدة = إعادة التشغيل. وهذا **حدّ صلب** غير قابل للتجاوز |
| **الإرجاع** | تلقائي عند نهاية المدة · أو يدوي فورًا · **بلا كلمة مرور** |
| **عند انتهاء المدة** | يعود تلقائيًا **بفحص كامل** لما تغيّر أثناء الغياب |
| **التذكير** | تنبيه واحد قبل 5 دقائق من العودة. لا أكثر |

| **الجملة الثانية تنفي الطمأنينة الزائفة** | «لن نتوقف عن التنبيه — سنتوقف عن الحماية» تمنع فهمًا خاطئًا شائعًا |
| **المسؤولية مكتوبة بلا لف** | «القرار قرارك، والمسؤولية عليك» — لا «ننصحك…» |
| **لا صندوق «أوافق على الشروط»** | لا نُجبره على توقيع؛ نُخبره ونمضي. صندوق الموافقة يُعلّم النقر الأعمى |
| **لا كلمة مرور ولا انتظار** | الحماية **بلا ابتزاز**. الحماية التي تُبتزّ بكلمة مرور تُكره المستخدم لا تُقنعه |
| **زر الخطر ليس الزر الأساسي** | «إلغاء» هو المرئي أولًا، و«إيقاف الحماية» بثانوي |
| **مدة محددة دائمًا** | لا يوجد «إلى الأبد» — وهذا هو الحدّ الوحيد الذي نفرضه |

### 4.4 ما لا يُغلق — الحمايات غير القابلة للإيقاف

حتى في إيقاف الحماية الكامل، **ثلاثة أشياء تبقى**:

| يبقى | لماذا |
|------|-------|
| **حماية العبث** (§5) | لا يمكن تعطيل Odina عبر تعديل ملفاته أو قتل خدمته |
| **حماية أحدث نسخة** | لا رجوع إلى قاعدة تهديدات قديمة |
| **الفحص عند العودة** | أول عمل عند الإرجاع: فحص كامل لغياب المدة |

### 4.5 حالات لا يُسمح فيها بالإيقاف مؤقتًا — والسبب أخلاقي لا تقني

| الحالة | الرسالة |
|--------|---------|
| **يوجد ملف معزول لم يُحسم** | «يوجد ملف معزول لم تحسمه بعد. راجعه أولًا.» |
| **فحص جارٍ الآن** | «هناك فحص جارٍ. انتظره أو أوقفه أولًا.» |
| **تهديد لم يُعالَج** | «يوجد تهديد لم يُعالَج بعد. لا نُوقف الحماية وتهديدها مفتوح.» |

**لماذا؟** لأن هذه الحالات الثلاث تعني أن هناك **شيئًا معلّقًا لم يقرره المستخدم بعد**. والإيقاف حينها لا يترك الجهاز بلا حماية فحسب — بل **يمنع المستخدم من رؤية ما كان سيُكتشف**. وهذا ليس حرية، بل انعدام لمعلومة ناقصة.

> **والتفرقة دقيقة ومقصودة:** نحن لا نمنعه من الإيقاف — نطلب منه أن **يُنهي ما بدأه أولًا**. وهذا يخدمه، لا يقيّده.

### 4.6 كيف يُعرض الإيقاف للمستخدم

| الموضع | العرض |
|--------|-------|
| الشاشة الرئيسية | الدرع **رمادي** + «الحماية موقوفة حتى 14:30» |
| الشريط المصغّر | رمز واحد بلون تحذيري |
| صينية النظام | «غير محمي — بقرارك» |
| زر الإرجاع | **ظاهر دائمًا في الشاشة الرئيسية** — بضغطة واحدة |

**ولا تُخفى الحالة أبدًا.** إخفاء «أنت غير محمي» هو الخداع الوحيد الذي لا نسمح به.

### 4.7 المسؤولية — كيف نضعها بلا تهديد

| لا نفعل | نفعل |
|---------|------|
| ❌ «أنت وحدك المسؤول عن أي ضرر» بخط صغير | ✅ «القرار قرارك، والمسؤولية عليك» في صلب الشاشة |
| ❌ نافذة تهديد عند كل إقلاع | ✅ **لا تذكير** بعد أن يُقرر — إلا تنبيه واحد قبل العودة |
| ❌ إشعار «لماذا أوقفت الحماية؟» | ✅ صفر سؤال. القرار لا يُحقَّق فيه |
| ❌ تعطيل الميزة بعد استعمال متكرر | ✅ **بلا حدّ**. من يوقف الحماية عشر مرات يوقفها الحادية عشرة |

**والسبب:** المستخدم الذي يُعاتَب على قراره **يكذب في المرة القادمة** — فيُطفئ الخدمة من مدير المهام بدل أن يستخدم الواجهة. والواجهة التي تُحترم تُستخدم، والتي لا تُحترم تُلتف حولها.

### 4.8 الاستثناء الجراحي — قاعدة واحدة، لا الكل (D45)

> **العيب الذي كشف هذا القسم:** كان إيقاف **كل** الحماية يحتاج ضغطة بلا سبب، بينما إرخاء
> **قاعدة واحدة** يحتاج وضع خبير وبيان سبب مكتوب. الفعل الأخطر كان أسهل من الأأمن. ومن
> يُقيَّد هكذا لا يطيع — بل يُطفئ الحماية كلها، أو يقتل الخدمة من مدير المهام. **التقييد
> الصامت يولّد الخطر الذي يريد منعه.**

الاستثناء ليس بابًا خلفيًا: هو **مفتاح لكل قاعدة على حدة**، مرئي، ومحدود، ولا يفتح غيره.

#### 4.8.1 ما يمكن استثناؤه — القائمة المغلقة

| القاعدة | المفتاح | أقصى استثناء | دائم؟ |
|---------|---------|--------------|-------|
| A1 · Windows Script Host | `a1.wsh` | سماح كامل | نعم |
| A1 · PowerShell | `a1.powershell` | سماح كامل | نعم |
| A1 · ماكرو Office | `a1.macros` | سماح كامل | نعم |
| A3 · اشتباه التنزيلات | `a3.downloads` | سماح كامل | نعم |
| A4 · الفحص الدوري | `a4.periodic` | سماح كامل | نعم |
| A6 · الحذر لا الشجاعة | `a6.doubt` | **إرخاء فقط** | **لا** |

**A6 لا يُسمح به أبدًا:** «اسمح بالشك» ليست إعدادًا، بل نفي للمنتج. يُرخَّى (يمنع عند
درجة عالية فقط) ولا يُلغى. و**لا استثناء دائم له** لنفس السبب.

#### 4.8.2 ما لا يُستثنى — أربعة خطوط

| لا يُستثنى | لماذا |
|-----------|-------|
| **حكم الجدار 1** | الاستثناء يُرخي **الوقاية**، ولا يُبرئ ملفًا. مؤكد ← لا تنفيذ؛ يُعالَج حتى تحت الاستثناء |
| **حماية العبث** (§5) | لا يُعطَّل Odina عبر تعديل ملفاته وقتل خدمته — ولو استُثني كل شيء |
| **قاعدة ثانية** | استثناء WSH لا يجعل PowerShell مسموحًا. العزل **يُختبَر** لا يُفترض |
| **مشتبه بشدة (≥ 0.80)** | الإرخاء يُسكت «مشتبه» (0.50–0.79)، ولا يمسّ «أوقف الآن» |

#### 4.8.3 المدد — والفرق بين المؤقت والدائم

| النوع | المدى | يحتاج | يظهر |
|-------|-------|-------|-------|
| مؤقت | 10 د · 30 د · ساعة · حتى إعادة التشغيل | زرّان، بلا سبب | شارة كاملة |
| دائم (مسار) | لا ينتهي | وضع خبير + شاشة عاقبة | شارة + سطر في الرئيسية |
| دائم (قاعدة كاملة) | لا ينتهي | وضع خبير | شارة + تنبيه شهري واحد |

#### 4.8.4 الأربعة التي نلتزم بها

1. **لا استثناء صامت.** كل استثناء حيّ يظهر: شارة في الرئيسية، وسطر في صينية النظام.
   إخفاء الاستثناء هو الخداع الوحيد الذي لا نسمح به — تمامًا كإخفاء «أنت غير محمي».
2. **بلا استجواب.** لا يُطلب سبب مكتوب. القرار لا يُحقَّق فيه (§4.7) — وهذا ينطبق على
   الاستثناء كما ينطبق على الإيقاف.
3. **التراجع أسهل من المنح، دائمًا.** ضغطة واحدة، بلا كلمة مرور، في كل مسار.
4. **الانتهاء يعيد ويفحص.** عند انتهاء المؤقت يُعاد الحكم، ويُفحص ما جرى في النطاق
   المستثنى أثناءه، ويُعرض دفعة واحدة (نمط D40).

#### 4.8.5 ما يحدث عند الانتهاء

| الحالة | السلوك |
|--------|--------|
| ملف مشتبه ظهر أثناء الاستثناء | يُعرض مرة واحدة عند العودة، في قائمة واحدة |
| ملف مؤكد ظهر أثناء الاستثناء | مُنع تشغيله رغم الاستثناء (الخط 1)؛ يُذكر مصيره الفعلي أو أنه لا يزال قيد المعالجة |
| لم يظهر شيء | لا إشعار. الصمت الجيد صمت |

## 5. حماية العبث (Tamper Protection) — إلزامية

| التهديد | الدفاع |
|---------|--------|
| إنهاء العملية | إشراف وإعادة تشغيل بصلاحية محدودة؛ المقيم التجريبي لنفس المستخدم، لا يُمنح حساب SYSTEM |
| تعديل قاعدة البيانات | توقيع رقمي على كل تحديث + تحقق SHA-256 قبل التحميل |
| تعديل إعدادات الحماية من خارج الواجهة | الإعدادات مقروءة من مفتاح محمي، لا من ملف عادي |
| تعطيل الخدمة من مدير المهام | إعادة التشغيل + تسجيل الحدث في السجل المحلي |
| **إسقاط الخدمة عبر تحديث مضاد** | **لا تحديث إلا بحزمة موقّعة** — لا تحديث بلا توقيع، مطلقًا |

**حدّ الاعتراف:** لا يوجد مكافح غير قابل للكسر بصلاحيات المدير. هدفنا ليس المنع المطلق بل **جعل العبث مكلفًا ومسجَّلًا**. ولا ندّعي غير ذلك.

## 6. قواعد التنبيه — كما تُنقل إلى الكود

| الحالة | عدد الأزرار | الأزرار | المدة قبل الانتهاء | القرار عند الانتهاء |
|--------|--------------|---------|---------------------|----------------------|
| مؤكد | **1** | متابعة المعالجة | لا يختفي | يستمر منع التشغيل والمعالجة، لا يُفترَض عزل |
| مشتبه بشدة | 2 | السماح · المنع | 60 ثانية | **منع** |
| مشتبه | 2 | السماح · المنع | 30 ثانية | منع مؤقت + فحص عميق |
| خطر متوسط (كراك) | 2 | انقله جانبًا · اسمح به | 30 ثانية | **لا عزل تلقائي** |
| معلوماتي | 0 | — | 10 ثوانٍ | تجاهل بصمت |

**قواعد إلزامية:**
- **لا تنبيه بلا قرار يملكه المستخدم.**
- **≤ 3 إشعارات/يوم** افتراضيًا؛ وما زاد يُجمَّع.
- **لا نافذة Modal أبدًا** — Toast أو Inline.
- **موقع التنبيه يتبع اتجاه الواجهة** (RTL: أسفل-يسار · LTR: أسفل-يمين).
- **لا تنبيهان لنفس الحدث.**
- **«عدم الإزعاج» يخفي المعلوماتية فقط** — لا يخفي المؤكد ولا المشتبه بشدة.

## 7. ماذا يحدث عند الفشل

الاعتراف الصريح شرط الثقة:

| الفشل | السلوك |
|-------|--------|
| تعذّر تحديث القاعدة | استخدام القاعدة الحالية + إشعار **واحد** بعد 7 أيام، لا كل يوم |
| تعذّر العزل (ملف مقفل) | تنبيه واحد بذلك، **بلا مطالبة بحذف** — والخيار: إعادة المحاولة لاحقًا |
| إنذار كاذب | إصلاح فوري + **اعتذار في نفس الشاشة** — لا في صفحة أخرى (§2.1) |
| تعطّل الخدمة | إعادة تشغيل + سجل محلي. **لا إرسال تقرير آلي** |
| ملف مصاب أثناء إسكات التنبيهات | **يُمنع ويُعالَج بصمت**، وتُعرض نتيجة المعالجة عند انتهاء المدة — لا يُترك بلا معالجة |
| انتهاء مدة إيقاف الحماية | فحص كامل فوري لما تغيّر، ثم عودة الحماية. بلا سؤال |
| كشف قاعدة لم تُحدَّث | استمرار العمل بالقاعدة القديمة، وصمت تام — **لا إشعار ذعر** |

## 8. ما لا يفعله Odina — وثيقة نفي

هذه حدود القراءة والموافقة والخصوصية:

| لا | لماذا |
|----|-------|
| ❌ لا يرفع ملفاتك | §9.3 — لا محتوى ملفات في التقارير، أبدًا |
| ❌ لا يجمع محتوى مستنداتك | قد يقرأ الملف المحلي لبصمته ضمن نطاق الفحص، ولا يرسل بايتات المستند أو مساره. استعلام D48 الأول لا يقرأ الملف أصلًا |
| ❌ لا يتصل بالشبكة بلا إذن | صفر تيليمتري. التحديث فقط، بموافقة |

| ❌ لا يبيع بيانات | لا بيانات أصلًا |
| ❌ لا يحذف ملفاتك | §1 — الحذف قرارك في العزل |
| ❌ لا يطلب اشتراكًا | مجاني بالكامل |
| ❌ لا يمنع برامج بلا سبب | ما دون 50% لا يُعرض عليك |

## 10. بوابة القبول لهذه الوثيقة

لا يُكتب سطر حماية قبل أن يجيب الكود على كل بند:

- [ ] صفر مسار كود يحذف ملفًا خارج صندوق العزل
- [ ] صفر اتصال شبكي بلا موافقة صريحة
- [ ] لا تنبيه بلا قرار
- [ ] ما دون 50% لا يظهر للمستخدم
- [ ] ترتيب تقييم الجدران محفوظ: 1 → 2 → 3 حيث ينطبق؛ لا تعادل العتبة تنشيط مراقب الجهاز
- [ ] اختبار مستقل لكل سبب مؤقت ولتداخل سببين؛ تحذير ذو شقين قبل الدائم، رجوع للخمول بعد آخر سبب دون تبديل التفضيل، ولا إعادة تنشيط أثناء إيقاف الحماية
- [ ] حزمة أساس بلا إضافة متصفح أو أتمتة: يعمل أمر Explorer، وصندوق العزل قابل للاسترجاع، ولا يتطلب غياب الوصفات أي تنزيل
- [ ] **Pause** يؤخر العرض فقط: تُحفظ الحادثة ونتيجتها وتُعرضان دفعة واحدة؛ لا يرفع الإسكات صلاحيات الإصلاح ولا يُنشّط وضع السلوك الدائم
- [ ] **إيقاف الحماية** يوقف كل شيء، وينتهي بمدّة، ويعود بفحص كامل
- [ ] لا مدة «دائمة» **لإيقاف الحماية**؛ لا يُخلط ذلك بتفضيل رصد السلوك أو استثناء خبير مسموح
- [ ] الحماية تُعاد **بلا كلمة مرور** وبضغطة واحدة
- [ ] حالات الرفض الثلاث (§4.5) مطبَّقة ورسائلها ظاهرة
- [ ] كل تحديث موقّع، ورفض غير الموقّع
- [ ] إنذار كاذب يُصلَح ويُعتذر عنه في نفس الشاشة
- [ ] **استثناء قاعدة لا يُغيّر قاعدة أخرى** (اختبار عزل إلزامي: WSH مفتوح ← PowerShell كما كان)
- [ ] **مؤكد يُمنع ويُعالَج تحت الاستثناء** (اختبار: سماح WSH + عيّنة مؤكدة ← لا تنفيذ)
- [ ] **مؤقت ينتهي في اللحظة** (اختبار: 30 د ← دقيقة 30 تمامًا لا قبلها ولا بعدها)
- [ ] **دائم مرئي دائمًا** (اختبار: لا مسار كود يخفي شارة استثناء حيّ)
- [ ] **A6 لا يُسمح ولا يُدَّمم** (اختباران يرفضان الطلب)
- [ ] **التراجع بلا كلمة مرور وبضغطة** (اختبار على كل مسار)

---

**الخلاصة:** المستهدف احتواء موثَّق وعزل قابل للاسترجاع بلا حذف تلقائي؛ لا أتمتة صيانة بلا اختيار، ولا اتصال بلا إذن.

**حد D48:** فحص تحديد من المتصفح قراءةٌ بطلب المستخدم وليس جدار تنفيذ؛ لا تُنسب إليه صلاحيات D46 أو إجراءات D47. لا اعتراض تصفح أو تنزيل، ولا تصعيد لملف مجهول. [عقد العميل المحلي](../browser-integration.md).
