# Odina — مخطط التقارير v1 (Report Schema)

> **الحالة:** ✅ معتمدة — 2026-11-16
> **المرجع:** `docs/odina-agent-prompt-v19.md` §11.1 · §4.5
> **القاعدة الحاكمة:** التقرير **اختياري تمامًا**، و**لا يحمل ما يعرّف المستخدم**. وإن تعارضت رغبة في التحليلات مع هذه الوثيقة، تلغي الرغبة.

---

## 1. المبدأ

> **نحن نطلب بصمة الملف لا بصمة الشخص.**

الملف الخبيث بياناته **ملك للجميع** — البصمة نفسها موجودة في ألف جهاز. أما **من** أصيب، و**أين**، و**متى** — فهذه بياناته، وليست من حقنا.

ولهذا التقرير يحتوي **توقيع الملف فقط**، لا إطارًا حول المستخدم.

---

## 2. الحقول — 16 حقلًا، ولا سابع عشر

| # | الحقل | النوع | إلزامي | الغرض |
|---|-------|------|--------|-------|
| 1 | `schema` | string | ✅ | `"odina-report/v1"` — نسخة الصيغة |
| 2 | `sha256` | string(64) | ✅ | بصمة الملف الكاملة |
| 3 | `size` | uint64 | ✅ | الحجم بالبايت |
| 4 | `header_hash` | string(64) | ⬜ | SHA-256 لأول 4KB |
| 5 | `tail_hash` | string(64) | ⬜ | SHA-256 لآخر 4KB |
| 6 | `pe_hash` | string(32) | ⬜ | Imphash للاستيرادات |
| 7 | `tlsh` | string | ⬜ | بصمة القرابة الضبابية |
| 8 | `name_pattern` | string | ⬜ | **نمط** الاسم لا الاسم (§3) |
| 9 | `path_pattern` | string | ⬜ | **نمط** المسار لا المسار (§3) |
| 10 | `attributes` | object | ⬜ | `{hidden, system, executable}` |
| 11 | `behavior_score` | float | ⬜ | نتيجة التقييم 0.0–1.0 |
| 12 | `behaviors` | string[] | ⬜ | رموز سلوكية معيارية (لا نص حر) |
| 13 | `family` | string | ⬜ | عائلة التهديد إن عُرفت |
| 14 | `app_version` | string | ✅ | إصدار Odina |
| 15 | `db_version` | string | ✅ | إصدار قاعدة التهديدات |
| 16 | `ui_lang` | string | ⬜ | **رمز اللغة فقط** — آخر حقل |

**ما ليس في الجدول ليس في التقرير.** لا حقل «ملاحظات»، لا «بيانات إضافية»، لا `extra: {}`. **الحقل الحر هو كيف تتسرّب البيانات.**

---

## 3. أنماط — كيف نحوّل اسمًا ومسارًا إلى نمط

هذا **أخطر مكان في المخطط**، وأكثر ما يمكن أن يتحوّل إلى تسريب بلا انتباه.

### 3.1 `name_pattern`

```
❌ خاطئ : "فاتورة_شركة_النور_2024.exe"
✅ صحيح : "[word]{3,12}_[word]{2,8}_[digits]{4}.exe"
```

**القواعد:**
- يُستبدل كل مقطع بحرفي بأطول فئة تناسبها (`[word]` · `[digits]` · `[single-char]`).
- يُحفظ **عدد المقاطع وترتيبها** فقط.
- **لا يُحفظ أي حرف من الاسم الأصلي** — لا أول حرف، لا أخير.

### 3.2 `path_pattern`

```
❌ خاطئ : "C:\Users\Ahmed\Downloads\فاتورة.exe"
✅ صحيح : "%USERPROFILE%\Downloads\<name>"
```

**القواعد:**
- `%USERPROFILE%` و`%TEMP%` و`%APPDATA%` **رموز معيارية**، لا مسارات حقيقية.
- اسم المجلد من المستخدم → `<dir>`
- اسم الملف → `<name>`
- **عمق المسار محفوظ** لأنه خاصية بنيوية مفيدة.

### 3.3 لماذا هذا كافٍ للتحليل

لأن ما نحتاج معرفته عن التهديد هو **بنيته**، لا هوية صاحبه: مسار في `Temp`؟ اسم بأربعة مقاطع؟ امتداد مزدوج؟ كل هذه **تنجو من التحويل إلى نمط**. أما اسم الشركة والمستخدم فلا يُضيفان شيئًا لقرار الحماية.

## 4. الصيغة الكاملة

```json
{
  "schema": "odina-report/v1",
  "sha256": "9f2a...c41e",
  "size": 524288,
  "header_hash": "1b7c...9a02",
  "tail_hash": "44de...0f18",
  "pe_hash": "b1a2c3d4e5f60718293a4b5c6d7e8f90",
  "tlsh": "T1A4B2C3D4E5F60718293A4B5C6D7E8F90A1B2C3D4E5F60718293A4B5C6D7E8F9012345",
  "name_pattern": "[word]{3,12}_[word]{2,8}_[digits]{4}.exe",
  "path_pattern": "%USERPROFILE%\\Downloads\\<name>",
  "attributes": { "hidden": false, "system": false, "executable": true },
  "behavior_score": 0.87,
  "behaviors": ["wsh_restricted_bypass", "startup_write", "temp_exec"],
  "family": "generic.dropper",
  "app_version": "0.1.0",
  "db_version": "2026.11.16",
  "ui_lang": "ar"
}
```

### 4.1 قواعد الصيغة

| القاعدة | التفصيل |
|---------|---------|
| **مفاتيح إنجليزية، قيم معيارية** | لا نص حر في أي حقل ما عدا `name_pattern` |
| **`behaviors` من قاموس مغلق** | `wsh_restricted_bypass` · `startup_write` · `temp_exec` · `usb_autorun` · `hosts_edit` · `net_attempt` · `self_delete` |
| **لا `ts` في التقرير** | الوقت لحظة الكشف بيانات إضافية عن المستخدم ولو ضمنا (منطقة زمنية). يُسجَّل محليًا فقط |
| **لا `hwid` · لا `ip` · لا `guid`** | ممنوع بأي حال |
| **`ui_lang` آخر حقل** | اختياري، معزول، ولا يُقرن بأي معرّف |

## 5. ما لا يُرسَل — القائمة السوداء

| ممنوع | لماذا |
|-------|-------|
| ❌ **محتوى الملف** (ولو جزئيًا) | ليس تهديدًا فقط، بل خصوصية محضة |
| ❌ **المسار الكامل** | يكشف اسم المستخدم وبنية جهازه |
| ❌ **اسم الملف الكامل** | غالبًا أسماء شركات وأشخاص عربية |
| ❌ **اسم المستخدم / اسم الجهاز** | معرّف مباشر |
| ❌ **HWID · MAC · Serial** | معرّف دائم |
| ❌ **IP · ASN · المنطقة** | معرّف شبكي |
| ❌ **لغة النظام · المنطقة الزمنية · البلد** | بيانات ديموغرافية |
| ❌ **توقيت الكشف** | يكشف نافذة الاستيقاظ — وقائمة الأصدقاء عند بعض الأسر |
| ❌ **قائمة البرامج المثبّتة** | إبهام المستخدم |
| ❌ **بريد · هاتف** | لا نقبلها أصلًا |

**قاعدة الحسم:** إن احتجت أن تسأل «هل هذا الحقل شخصي؟» — **فهو شخصي، احذفه**.

## 6. الموافقة — كيف تُطلب

| القاعدة | التنفيذ |
|---------|---------|
| **opt-in صريح** | مُطفأ افتراضيًا. لا «مُفعّل مسبقًا مع إمكانية الإلغاء» |
| **لحظة الطلب مناسبة** | بعد أول كشف ناجح مفيد، لا في التثبيت |
| **عيّنة مرئية** | يُعرض **العنصر الكامل** المراد إرساله قبل الموافقة |
| **موافقة لا تغطي المستقبل كله** | «أرسل هذا التقرير» ≠ «أرسل كل التقارير» |
| **الإلغاء فوري** | زر واحد، بلا أسئلة، بلا «هل أنت متأكد؟» |
| **بلا مقابل** | لا نُعطي شيئًا مقابل الموافقة — ولا نُهدّد بشيء عند الرفض |

**وأهم قاعدة:** الرفض **لا يغيّر مستوى الحماية**. المستخدم الذي يرفض كل التقارير يحصل على نفس الحماية تمامًا، وعلى قاعدة تحديث أبطأ بطبيعتها — **ونقول له ذلك بصراحة، لا كعقاب**.

## 7. النقل — كيف يُرسَل إن أُرسل

| البند | القاعدة |
|-------|---------|
| **البروتوكول** | HTTPS فقط. لا HTTP، لا DNS بلا TLS |
| **التوقيع** | كل تقرير موقّع بمفتاح Odina — يُرفض غير الموقّع |
| **الدمج** | لا إرسال فورًا. يُجمع في `outbox` ويُرسَل عند توفر الشبكة |
| **الحجم** | حد أقصى 4KB/تقرير — يمنع التسريب بالحجم |
| **الفشل** | يُعاد المحاولة 3 مرات ثم يُحذف. **لا طابور لا نهائي** |
| **الجدول** | **Google Sheets** هو وجهة التجميع الحالية (§9.4) — للمرحلة المبكرة فقط |

## 8. النسخ والتوافق

| القاعدة | التفصيل |
|---------|---------|
| `schema` إلزامي | `odina-report/v1` |
| **إضافة حقل = نسخة جديدة** | `v2` لا `v1` مع حقل صامت |
| **حقل جديد دائمًا اختياري** | الخادم يجب أن يقبل `v1` بلا الحقل الجديد |
| **لا تكسير** | لا حذف حقل، لا تغيير نوع، بلا رفع النسخة |
| **عمر التقرير** | يُحذف على الخادم بعد 180 يومًا |

## 9. الاستخدام — ماذا نفعل بالتقارير

| الاستخدام | مسموح | ملاحظة |
|-----------|-------|--------|
| تحديث قاعدة التهديدات | ✅ | الغرض الأول |
| بناء clean corpus | ✅ | من التقارير السالبة المؤكَّدة |
| تحسين الأوزان | ✅ | §7 من `scoring-spec-v1` |
| تصحيح الترجمة | ✅ | `ui_lang` وحده — لغة **الواجهة**، لا المستخدم |
| **بيع البيانات** | ❌ | لا يوجد ما يُباع أصلًا |
| **مشاركة مع طرف ثالث** | ❌ | ولو «للتحقق» |
| **ربط تقارير بجهاز واحد** | ❌ | لا معرّف أصلا |

**قاعدة الخادم:** البيانات تُجمَّع **مجهولة بحكم التصميم**، لا بحكم السياسة. أي حقل يربط تقريرين بجهاز واحد ممنوع في المخطط نفسه.

## 10. بوابة القبول

- [ ] 16 حقلًا بالضبط — اختبار يفشل إن ظهر حقل غير معلن
- [ ] `name_pattern` و`path_pattern` لا يحتويان أي حرف من الاسم/المسار الأصلي (اختبار بـ 100 اسم عربي)
- [ ] لا `ts` · لا `ip` · لا `hwid` في أي نسخة
- [ ] opt-in مُطفأ افتراضيًا في الكود
- [ ] الرفض لا يغيّر مستوى الحماية (اختبار سلوكي)
- [ ] الحجم ≤ 4KB لكل تقرير
- [ ] التوقيع إلزامي، وغير الموقّع يُرفض
