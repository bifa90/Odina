# نسخة الفحص — نسخة المستخدم نفسها، مع طبقة قياس محلية

> **الحالة:** البنية جاهزة وتُبنى في CI · **لم يُنتج ملف تنفيذي بعد**، ولا تقرير واحد حقيقي
> **الملف التنفيذي:** `crates/odina-cli` بـ`--features instrument`
> **السكيما:** `odina-perf/v1` (القياس) + `odina-report/v1` (التقارير) في ملف واحد
> **المرجع:** `docs/odina-agent-prompt-v17.md` §34 · §35 · `docs/spec/report-schema-v1.md`

---

## 1. ما اتفقنا عليه، بالحرف

> «نسخة الفحص = نسخة المستخدم + كود مراقبة وتقارير مدمج مع النسخة.»

وهذا هو التنفيذ الحرفي: **مصدر واحد، وملف تنفيذي واحد، وسطر بناء واحد.** الفرق الوحيد بين النسختين هو
`--features instrument`، وليس فرعًا ولا نسخة معدّلة ولا مستودعًا ثانيًا. أي إصلاح يصل إلى النسخة العامة
يصل إلى نسخة الفحص بالبناء نفسه، فلا تتباعد النسختان بعد أسبوعين.

| | النسخة العامة | نسخة الفحص |
|---|---|---|
| الأمر | `odina scan` · `odina selftest` | نفس الأمرين، ويُضاف `odina check` |
| الروابط | `odina-core` فقط | `odina-core` + `odina-report` + `odina-instrument` |
| الشبكة | لا شيء | **لا شيء أيضًا** — لا مقبس ولا عنوان في الشيفرة |
| ما يُكتب | لا ملف | ملف JSON محلي واحد، أنت من يرسله |
| البوابة | `check-public-build` تمنع أي كود قياس من التسرب إليها | تُبنى وتُختبر في `rust.yml` |

**البوابة هي الضمانة، لا الوعد.** `tools/ci/check-public-build.py` يفحص أن الحزمتين
`optional = true`، وأن ميزة `instrument` ليست في `default`، وأن وحدة `check` محجوبة بـ`cfg`،
ثم يشغّل `cargo tree` على البناء الافتراضي ويفشل إن ظهر اسم أي من الحزمتين في شجرة الروابط.
وقد اختُبرت سلبًا: تُفشل البوابة بـ3 طرق مختلفة (وحدة غير محجوبة · حزمة غير اختيارية · ميزة مفعّلة افتراضيًا).

## 2. ماذا يقيس `odina check` بالضبط

### 2.1 ما يُقاس فعلًا اليوم (على Linux وWindows، بلا ويندوز مطلوب للبناء)

| المقياس | المصدر | الحالة |
|---|---|---|
| RAM للعملية (MB) | عدّاد نظام التشغيل لنفس العملية | ✅ يُقاس |
| الإنتاجية (ملف/ثانية) | ساعة العملية ÷ عدّاد الملفات | ✅ يُقاس |
| CPU متوسط أثناء الفحص (%) | فرق زمن CPU ÷ الزمن الحقيقي | ✅ يُقاس |
| عدد الملفات والبايتات | عدّادات المحرك نفسه | ✅ يُقاس |
| توزيع الأحكام (آمن · مراقبة · مشتبه · خطير · مؤكد) | نفس نتيجة `scan` | ✅ يُقاس |
| الملفات التي تعذّرت قراءتها | `scan` نفسه | ✅ يُقاس |

### 2.2 ما لا يُقاس، ويُكتب صراحة أنه لم يُقس

الباقي من §34.2 — أحد عشر مقياسًا — يحتاج أجزاء من المنتج غير موجودة بعد.
والفرق بين مشروع صادق وآخر ليس أن يقيس كل شيء، بل أن **يقول أي شيء لم يُقس**. لذلك كل بوابة
غير مقيسة تُكتب في الملف بالشكل:

```json
{"gate":"p0_ms","status":"unmeasured","reason":"needs a verdict path (C1)"}
```

وليس `0`. لأن `0` تعني «قِيس وكان صفرًا»، وهي أنجح ما تكون في تقرير يفترض القارئ أنه نجاح.
اختبار في `crates/odina-instrument/src/perf.rs` يمنع ظهور `"value":0` لبواية لم تُقس.

| البوابة | الشرط | سبب عدم القياس الآن |
|---|---|---|
| CPU خمول | = 0 | يحتاج التطبيق المقيم (B1)؛ أداة سطر أوامر تنتهي قبل أن تخمل |
| RAM أثناء USB | ≤ 50MB | يحتاج استيقاظ USB (C1) |
| CPU ذروة | ≤ 5% | يحتاج خيط أخذ عينات؛ الفحص هنا يمر واحدة |
| استيقاظ USB | < 50ms | يحتاج C1 |
| زمن P0 · P1 | < 3000 · < 15000ms | يحتاج مسار قرار (C1) |
| AMSI لكل سكربت | < 15ms | يحتاج موفّر AMSI (C5) |
| تبديل اللغة | < 100ms | يحتاج الواجهة (B1) |
| ذاكرة لكل لغة | ≤ 3MB | يحتاج الواجهة (B1) |
| I/O في الخمول | = 0 | يحتاج التطبيق المقيم (B1) |

## 3. التقارير — ستة عشر حقلًا، وتُبنى بالشيفرة لا بالوعد

`odina check` لا يُصدّر تقريرًا لكل ملف، بل **لما يستدعي تنبيهًا فقط** (مشتبه وما فوق). تصدير
كل ملف سليم يحوّل تصميمًا يحمي الخصوصية إلى جرد لقرص شخص.

| الحقل | ما يخرج فعلًا | ما لا يخرج أبدًا |
|---|---|---|
| `sha256` · `size` | بصمة الملف وحجمه | — |
| `header_hash` · `tail_hash` | أول 4KB وآخر 4KB | — |
| `pe_hash` | imphash من جدول الاستيراد، إن كان الملف PE | — |
| `name_pattern` | `[word]{4,8}.pdf.exe` مثلًا | **أي حرف من الاسم** |
| `path_pattern` | `%USERPROFILE%\<dir>\%DOWNLOADS%\<name>.exe` | المسار، اسم المستخدم، اسم المجلد |
| `attributes` | three booleans فقط | المالك، الأوقات، الصلاحيات |
| `behavior_score` | الشريحة (0 · 0.25 · 0.6 · 0.85 · 1.0) | النتيجة الخام والأوزان |
| `behaviors` | من قاموس مغلق من 7 رموز | أي نص حر |
| `app_version` · `db_version` | إصدارات | — |
| `ui_lang` | رمز لغة الواجهة، آخر حقل | أي شيء عن لغة المستخدم |
| `tlsh` · `family` | غائبان حتى يشحن TLSH وقاعدة التهديدات | قيمة ملفّقة |

**الحارس:** كل مقطع في النمط يجب أن ينتمي إلى مفردات ثابتة (`[word]{n}` · `[digits]{n}` ·
`[char]` · رمز مجلد · `<dir>` · `<name>` · امتداد معروف). وإن خرج مقطع عن المفردات —
أي إن تسرّب حرف واحد بسبب تعديل مستقبلي — تُستبدل النمط كله بـ`[redacted]`، فيظهر العطل
بدل أن يظهر الاسم. اختبار يدفع الحارس مباشرة ويؤكد أنه يرفض `[word]{4,8}Ahmed.exe`.

## 4. كيف يُبنى ويُشغَّل

```bash
# النسخة العامة — بلا كود قياس
cargo build --release --locked
cargo tree -p odina-cli --edges normal      # odina-report غير موجودة

# نسخة الفحص
cargo build --release --locked --features instrument
odina check ~/Downloads --out odina-check.json
```

ثم ترسل الملف الناتج — أو تفتحه وتقرأه أولًا، وهذا هو الأصل — أو تحذفه ولا يحدث شيء.

**الملف واحد** ويحتوي كائنين: مقاييس `odina-perf/v1` ومصفوفة `reports` من `odina-report/v1`،
حتى لا يضيع القارئ بين ملفين مختلفَي البنية.

## 5. ما يكشفه هذا الملف عن المنتج (قبل أي إرسال)

| السؤال | كيف يُجاب من الملف |
|---|---|
| هل الذاكرة تنمو مع عدد الملفات؟ | `ram_idle_mb` مقابل `scan.files` |
| هل المحرك يرفع إنذارات كاذبة؟ | `scan.monitor` مقابل `scan.clean` |
| هل الفحص بطيء على مجلد حقيقي؟ | `throughput_files_per_sec` |
| هل أي ملف لم يعد يُقرأ؟ | `scan.unreadable` |
| هل البصمات تُحسب فعلًا؟ | `reports[].pe_hash` موجودة لملفات PE |

وهذه هي البيانات التي تُصحّح بها الأوزان (`scoring-spec` §7)، لا الأرقام المخترعة.
