**الحالة:** مرحلة التخطيط أُغلقت (2026-11-15). التنفيذ جارٍ: النواة وسطر الأوامر ونسخة القياس تُبنى وتُختبر على Windows وLinux. الفحص الحالي للقراءة فقط؛ لا توجد بعد قاعدة تهديدات إنتاجية أو حماية مقيمة.

## المهمة — ثلاثة أهداف لا تُفاوَض

| # | الهدف | المعيار |
|---|-------|---------|
| 1 | **خفيف على الموارد** | < 20MB RAM خمول · 0% CPU خمول |
| 2 | **قوي في الفحص، خاصة USB** | ≥ 99.5% من العينات المرجعية |
| 3 | **قاعدة بيانات ضخمة** | ≥ 3 مليون تهديد — **بلا سقف أعلى مفروض** |

**القاعدة الذهبية:** *«الحجم وسيلة، لا غاية. القوة هي الغاية.»*

## ماذا يحدث بعد تأكيد الإصابة؟

منع التشغيل لا يعني عزل الملف. بعد تقييم الجدران الثلاثة يُحيَّد الخطر، ويُطهَّر المضيف بوصفة مطابقة، ثم تُصلح الأضرار ويُعاد الفحص. العزل آخر حلّ للبرمجية الخبيثة نفسها أو عند تعذّر التطهير الآمن.

[قاعدة الإصلاح](docs/spec/repair-component-v1.md) مكوّن بيانات مستقل عن قاعدة التهديدات. تُرفق بحزمة ويندوز حتى 100 MB، وتُنزل منفصلة فوق ذلك. في الحزمة المفكوكة يشغّل `odina.exe repair-db --demo` وصفتين تدريبيتين في الذاكرة. المعالجة الفعلية على ويندوز ووصفات العائلات الإنتاجية ليستا جاهزتين بعد؛ `scan` لا يغيّر ملفاتك.

## أسس الثقة — دستور الواجهة

1. **الوضوح** — نقول ما حدث، لا ما هو التقنية.
2. **البساطة** — زرّان كحد أقصى. صفر إعداد مطلوب.
3. **الطمأنينة** — بلا حدث = بلا نافذة. ≤ 3 إشعارات يوميًا.
4. **معرفة العواقب** — عاقبة كل زر مكتوبة قبله لا بعده.

**وعند التعارض:** الأمان ← عدم الإزعاج ← الوضوح ← البساطة ← الجمال.

**قاعدتان لا تُخترقان:**
- **لا زر «حذف» في أي تنبيه** — الحذف فقط داخل صندوق العزل.
- **صفر تيليمتري.** لا شيء يُرسَل إلا بموافقتك الصريحة.
